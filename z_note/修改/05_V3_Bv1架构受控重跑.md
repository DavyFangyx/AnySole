# 修改 05：V3_Bv1 架构现役口径受控重跑（1 次训练）

## 一句话目标

T2M PA 有两个独立证据指向 ~82（V3_Bv1_denoised 80.7、外部 Step2Motion 82.6），现役线停在 89.4。本修改用一次受控重跑把这 6.7 mm 归到**配方/架构**或**数据协议变更**，并同时关闭「老线数字作废」的悬置争议。

## 为什么（先更正一个错误前提）

**V3_Bv1 与 V7_Cv5 都是确定性回归，不是「旧扩散 vs 新回归」。**已核：

- `MODEL_ANYSOLEV2 = "anysolev2"`（`anysole/models/common/model_v2.py:31`）
- `regress_mode = checkpoint_modal == MODEL_ANYSOLEV2 and not v3f`（`anysole/eval.py:660`）
- 两个 cell 的 `metrics/test.json` 里 `modal` 均为 `anysolev2`，`v3f` 均缺省 → 推理期都不采样（`sample_steps=50` 被记录但不消费）

所以「换生成载体」这条解释作废，归因范围收缩到一份可枚举的差异清单。

### 同口径重算（主会话 2026-11-03）

用**今天的 GT、同 36 会话、同一逐帧相似对齐 PA** 从各自导出 npz 重算：

| cell | T2M PA | 覆盖帧 |
|---|---|---|
| V3_Bv1 | 82.71 | 12520 |
| V3_Bv1_denoised | 80.65 | 12520 |
| V7_Cv5_s1 | 89.39 | 12500 |
| 常数均值姿态地板（train 拟合） | 104.1 | — |

指标层面对等（同 GT、同定义、同会话集）；差异在各自当年的数据处理与训练划分，这正是本修改要隔离的变量。

### 伴随的机制线索

| 量 | V3_Bv1 | V7_Cv5 | GT |
|---|---|---|---|
| T2M PA | 82.7 | 89.4 | — |
| 窗内（非接缝）jerk | 1862 | **217** | 130 |
| body_motion_rms | 118.6 | 100.7 | 111.5 |

Cv5 窗内比 GT 还光滑、幅度比 GT 小 10%，PA 差 6.7 mm——**过度平滑 / 幅度不足**的签名。V3_Bv1 幅度略高于 GT、窗内偏抖，但姿态更准。

### 已知差异清单（配置实测 diff）

`results/cells/V3_Bv1/effective_config.json` vs `V7_Cv5_s1/effective_config.json`：

| 项 | V3_Bv1 | V7_Cv5 |
|---|---|---|
| 架构入口 | `v3_3b`（9 部位 + soft A + sigma 门） | `v7_c2`（根/姿态双 T 信任门） |
| 条件采样 | 缺省（随机 dropout 世代） | `condition_sampling=enum` 枚举三条件 |
| contact_method | `joint_and` | `f6_soft_time_accel_state_smpl24_v1` |
| smpl_support_policy | 缺省 `legacy_clip` | `exclude` |
| 损失键位 | `lambda_assign 0.05` / `lambda_sigma 0.01` / `sigma_freeze_frac 0.1` | `lambda_pose 3.0` / `lambda_traj 1.0` / `lambda_contact 1.0` / `lambda_air 2.0` |
| tw | 20 | 20 |

另有不在 config 里的差异：训练/测试划分与上游数据处理在两者之间变更过多次（这是 11-02 作废裁定的依据）。

## 要做什么

### 主格：v3_3b 架构 + 现役数据协议

用 `anysole/registry.py` 已有的 `V3_Bv1` 架构入口（`v3_3b`，模块未删），在**完全现役的数据与协议**下重训一次：

- `contact_method = f6_soft_time_accel_state_smpl24_v1`
- `smpl_support_policy = exclude`
- canonical `splits.csv`（train 92 / val 12 = S12 / test 36 = S13+S14）
- `seq_root/cache_root` = cam3 现役默认
- tw=20、seed=1、评估走现役 `test_brief` 十指标口径
- 其余训练配方（ep / bs / lr / warmup / grad_clip）与 V7_Cv5_s1 对齐，差异项逐条登记

命名建议 `V3_Bv1_live`（entry 复用 `v3_3b`），双 registry 注册，conf 手工落盘 `configs/queue/`。

### 读数规则（预注册，三种结果三种结论）

| 重跑 T2M PA | 结论 | 后续 |
|---|---|---|
| ≈ 82 ± 2 | 6.7 mm 来自**配方/架构**，数据协议变更不是主因 | 11-02 作废裁定应按维度修订；把 v3_3b 的有效成分（soft 部位 / sigma 门 / 损失配比）移植进 V7 骨架 |
| ≈ 89 ± 2 | 6.7 mm 来自**数据协议变更**，老线 82 在现役数据上不可达 | 11-02 裁定成立；目标水位改以 Step2Motion 82.6 为唯一外部参照 |
| 居中（84–87） | 两者各占一部分 | 按占比决定是否继续拆（下一层变量 = contact_method 与 smpl_support_policy 各一格） |

### 伴随诊断（与主格同批出，不额外训练）

对重跑 ckpt 出 01/02 的两张剖面表（窗内 jerk + PA 剖面）与 `body_motion_rms`，与上面的机制线索表并排。目的是检验「过度平滑/幅度不足」这条解释是否随架构一起转移。

## 验收判据（预注册）

1. 重跑 cell 的 `evaluation_contract` 会话集与 `V7_Cv5_s1` **集合相等**（无差集），`contact_method` 命名空间通过 `e_results_export.py` 的 provenance 校验。
2. 三张表落盘：十指标对照（重跑 / V3_Bv1 历史 / V7_Cv5）、窗内剖面、幅度。
3. 按上面的读数规则给出结论归属，**三种结果都是有效交付**，不要求落在某一格。
4. 若训练中断：按既有纪律自动归档回队重跑，只报次数。

## 边界

- 不修订「老线数字作废」裁定本身——本修改只提供证据，裁定由用户下。
- 不改 `v3_3b` 的架构代码（它是被测对象，改了就不是受控对照）。只允许为适配现役数据契约做必要的接口对齐，且每处对齐逐条登记。
- 不把重跑数字直接写进 E2 主表；先出对照表。
- 不碰 `configs/z_gen/common.py`；注册 conf 保持默认值（首跑置 true 由用户手动）。
- 训练卡限 cuda:4/5/6/7。

## 交付物

1. `V3_Bv1_live` 双 registry + conf 落盘 + 训练完成的 cell。
2. 三张对照表（主干表根层，说明 md 下沉 `detail/`）。
3. 一条 commit（`[Model][V3] v3_3b 现役口径受控重跑`），不 push。
4. 回报：一行汇总 + 读数规则对应的结论归属 + cell 路径。
