# 修改 08：V/VT 平移锚头（V7_Cv5TA）

立项：2026-11-04。依据：`results/diagnostics/20261104_t_row_observability/measurements.md` §9–§11
（本轮新增三份探针：`anchor_observability.py`、`anchor_pressure_only.py`、`anchor_replacement_cost.py`）。

与 07 相互独立，可分别训练。07 动的是**窗内速度的参数化**，08 动的是**窗外那一个常数平移**；
两者在代码上不相交（07 在 `root_head` + `_trajectory_losses`，08 在新头 + 新损失项 + 新评估列）。

## 一句话目标

现役协议每 20 帧窗加一次 GT 平移锚（`eval_protocol.py:891` `anchor = batch["trans_anchor"][:, None, :]`，
`:1031` `out["trans_hat"] + anchor`，`n_gt_anchors_used = 494`）。本修改加一个**只读出、不回传**的
平移锚头，让 V/VT 行自己产出那个常数，从而把 `GlobalMPJPE` / `W-MPJPE100` / `root_rte_percent`
这几列**并列**补一组不消费任何 GT 锚的读数。现役列一个不动、一个不删。

## 测量依据（四条，每一条都钉住一个设计决定）

1. **世界系是固定房间系，不是会话相对系**（§9）。27 会话首帧 GT pelvis 跨会话 std = (0.057, 0.044, 0.726) m：
   x 几乎不动、y = 骨盆高、z 分「原地 ≈ 0」与「长走 ≈ −1.8 → +1.9」两簇。
   锚是 x ∈ [−0.2, 0.2] / y ∈ [0.4, 1.3] / z ∈ [−2.1, 1.9] 的**有界绝对位置**，固定相机下可观测。
   → 决定了「锚头估绝对量」这件事本身是良定义的。
2. **锚可以从 V 读出来**（§10）。线性岭回归、逐会话留一 27 折：
   全 2051 维 **187.4mm vs 地板 429.4mm（−56.3%，23/27 折）**；
   仅 CLIFF `bbox_info` 3 维就 **265.0mm（−38.3%）**；仅 HRNet 2048 维 339.4mm（−21.0%）。
   → 决定了锚头输入走 V 支路，且这不是碰运气：`bbox_info`（`extract_hrnet.py:246-254`，
   归一化裁剪框中心偏移 ×2.8 + 框尺寸归一化，focal 608.0）正是 CLIFF 复原相机系绝对平移用的三个量。
3. **锚读不出压力**（§10）。纯压力特征、留一受试者 7 折：W=20 −1.3% / W=100 −3.4% / W=200 −7.0%。
   → 决定了 T 行锚 = 注册常数，`L_tanchor` 对 T 行掩码（与 ctx4b「T 行锚 = 链/恒等，不训头」同款）。
4. **锚误差几乎 1:1 进入绝对读数**（§11）。根绝对 RMSE：GT 锚 164.1mm → 岭回归锚 427.8mm（锚自身 379.6mm）
   → 常数锚 732.0mm（锚自身 692.4mm）。
   → 决定了本修改的全部精度都压在锚头一个模块上，轨迹支路不需要动；也决定了验收判据直接写在锚误差上。

## 改动清单

### 改动 A：平移锚头（结构变更 → 新版本号）

**文件**：`anysole/models/common/model_v7.py`

A1. 构造（照 `:534-556` 的 ctx4b 模板逐行对应，**RNG 存/复 → init 逐位 Cv5 契约**）：

```python
if self.trans_anchor_head:
    # 修改 08：V/VT 行平移锚头。m_v 窗口均值 → 归一化残差 → 锚。
    # 零初始化 ⇒ init 锚 = anchor_mean（= 最佳常数地板，与 ctx4b 的
    # 「恒等 6D 起跳」同角色）；RNG 存/复构造保证与 Cv5 init 逐位相同。
    _rng = torch.get_rng_state()
    self.anchor_trans_off = nn.Sequential(
        nn.Linear(d, d), nn.GELU(), nn.Linear(d, 3))
    nn.init.zeros_(self.anchor_trans_off[-1].weight)
    nn.init.zeros_(self.anchor_trans_off[-1].bias)
    torch.set_rng_state(_rng)
    self.register_buffer("anchor_mean", torch.zeros(3))
    self.register_buffer("anchor_scale", torch.ones(3))
```

A2. 统计 buffer 由 `train.py` 在首步前拟合一次后冻结，与 `pose_mean/pose_std`
（`model_v7.py:236-241` + `train.py:2193-2197` `fit_pose_stats`）同机制、同位置、同一轮数据遍历：

```python
def set_anchor_stats(self, mean, scale):   # 与 set_stats 同款签名
    self.anchor_mean = mean.to(self.anchor_mean.dtype)
    self.anchor_scale = scale.to(self.anchor_scale.dtype)
```

`train.py` 侧新增 `fit_anchor_stats(loader, device)`：一遍训练 loader，`batch["trans_anchor"]`
的逐轴均值与标准差，`scale` 下限 1e-2 m（与 `fit_pose_stats` 的 std 下限同口径）。

**为什么要逐轴归一化**：三轴量程差 5 倍（§10 逐轴地板 x 73.7 / y 126.0 / z 350.5 mm）。
不归一化则等权 MSE 被 z 独占，x/y 不会被训练；归一化后三轴等权。

A3. 前向（紧跟 `:712-728` 的 `anchor_rot` 分支，**`m_v` 必须 detach，见下方零税契约**）：

```python
anchor_trans = None
if self.trans_anchor_head:
    feat = m_v.mean(dim=1)
    if self.trans_anchor_stopgrad:
        feat = feat.detach()
    anchor_trans = (self.anchor_mean
                    + self.anchor_scale * self.anchor_trans_off(feat))   # (B,3)
```

A4. `out` dict 增键 `"anchor_trans"`（`:793-810` 的返回体内，紧邻现有 `"anchor_rot"`）。
**`trans_hat` 的形状与语义一字不动**——锚头是旁路读出，不进 `cumsum`。

A5. 构造参数 `trans_anchor_head: bool = False`、`trans_anchor_stopgrad: bool = True`
加入 `AnySoleModelV7` 签名，由 STRUCTURE 标志驱动，默认关。

> **零税契约（本修改最重要的性质）**：`feat = m_v.mean(1).detach()` ⇒
> `∂L_tanchor/∂θ_主干 ≡ 0`。Adam 逐参数更新互不耦合，叠加 A1 的 RNG 存/复
> （init 逐位相同）与数据取样顺序不变（不新增任何 RNG 消费），**主干的每一步更新
> 与 Cv5 在数值上相同**，现役每一列读数不需要重新验证。
> 代价是锚头只能读主干已有的表征、不能反过来塑造它。放开 detach 是第二臂
> （`trans_anchor_stopgrad=False`），留在同一个标志位上，本轮不开——
> 两个结构变更混在一次训练里会毁掉归因。

### 改动 B：锚损失（T 行掩码）

**文件**：`anysole/utils/losses.py`

B1. `compute_losses_v7`（`:1126`）内，紧跟现有 `l_anchor` 块（`:1155-1163`）新增：

```python
l_tanchor = l_pose.new_zeros(())
if out.get("anchor_trans") is not None:
    # 修改 08：平移锚监督。归一化残差上的 smooth_l1（对异常窗比 MSE 稳），
    # 仅 V 在场行（T 行锚 = 注册常数，不训头——§10 实测压力对绝对位置
    # 只有 −1.3~−7.0%）。掩码机制与 l_anchor 的 config_id != CONFIG_T 同款。
    scale = model_anchor_scale.to(l_pose.device)          # 经 out 透传或 batch 侧传入
    diff = (out["anchor_trans"] - batch["trans_anchor"]) / scale
    per_sample = F.smooth_l1_loss(diff, torch.zeros_like(diff),
                                  reduction="none", beta=1.0).mean(dim=-1)
    l_tanchor = _masked_mean(per_sample, config_id != CONFIG_T)
```

B2. 总装（`:1213-1221`）增一项 `+ _weight(weights, "lambda_tanchor", 0.0) * l_tanchor`，
默认 0.0 ⇒ **未注册该键的所有老格行为逐位不变**。

B3. 返回 dict 增键 `"L_tanchor"`（现有键一个不删），`train.py` 日志装配同步。

B4. 权重由入口文件 `CONFIG_EXTRA` 提供，不新增 CLI 旗标——与 ctx4b 的
`CONFIG_EXTRA: dict = {"lambda_anchor": 1.0}`（`anysole/models/v7_c2ctx4b.py:17`，
经 `train.py:1700,2120` 与 `eval.py:463` 并入 config）逐条对应：


### 唯一缺陷：零税契约被「多走一遍 loader」打破

A2 原文是「与 `pose_mean/pose_std` 同机制、**同位置、同一轮数据遍历**」。
实现做到了同机制与同位置，**没有做到同一轮遍历**——`fit_anchor_stats` 是在
`fit_pose_stats` 之后**再开一遍**训练 loader（`train.py:2227`）。

训练 loader 是 `shuffle=True, generator=None`（`train.py:1993-2000`）。这种 loader
每创建一次迭代器，`RandomSampler.__iter__` 都要从**全局 CPU RNG** 抽一个种子
（多 worker 时 `_base_seed` 再抽一次）。实测（torch 2.4.0+cu121）：

```
遍历一遍 shuffle=True loader 后，全局 CPU RNG 状态改变?  True
num_workers=0  首个训练 epoch 的样本顺序与少一遍时相同?  False
num_workers=2  同上                                      False
get/set_rng_state 可完全中和?                            True
```

⇒ TA 比 Cv5 多消费一次全局 RNG ⇒ 此后每个 epoch 的 shuffle 种子都不同
⇒ **整轮训练的数据顺序与 Cv5 不同** ⇒ 主干不再「每一步与 Cv5 数值相同」。

`detach()` 与 A1 的 RNG 存/复都没问题，断的是零税契约的第三条前提（取样顺序不变）。
后果不是功能错误，而是**验收判据 1 失去可证性**：现役四列会浮出一层 run-to-run 漂移，
而判据 1 写的是「若读数有差，就是契约破了，当缺陷查」——届时会把一个已知的
数据顺序差读成结构缺陷。

**修法（二选一，都是一行级）**：

- 首选，复用 A1 同一套先例，把统计拟合包进 RNG 快照：
  ```python
  _rng = torch.get_rng_state()
  anchor_mean, anchor_std = fit_anchor_stats(loader, device)
  torch.set_rng_state(_rng)
  ```
- 或落实字面的「同一轮遍历」：把锚的 sum/sumsq 并进 `fit_pose_stats` 的循环。

**precheck 为什么没抓到**：步 1 判据是「`trans_anchor_head=False` 时 init 逐位相同」，
测的是模块构造期 RNG，与数据顺序无关；而 flag=False 时 `fit_anchor_stats` 压根不执行。
补一条判据：**flag=True 跑 1 epoch，`epoch=1 step=0` 的 `L_pose` / `L_contact` 与同配方
Cv5 逐位相同**——step 0 尚未更新参数，这两个数只由 init 与首批数据决定，是数据顺序的
直接指纹。现缺一个同配方 `V7_Cv5_precheck` 对照格，建议补跑 6 轮当常备标尺。

**时机**：`V7_Cv5TA_act8020_s1` 尚未入队（running 只到 `00045__V7_Cv5TA_precheck`），
改完再投，零返工。

## 边界

- 现役列、现役求解器、`gt_trans` 侧、`trans_hat`、FK、`L_foot`、`L_traj` **一行不改**；新列只增不替。
- `n_gt_anchors_used` 保持 494 逐位不变（修改 02 硬约束）。
- `trans_anchor_head=False` 时全链逐位等价于现役 Cv5。
- 锚**每窗独立估计**，不做窗间链式递推、不做时序平滑——Cv5「误差不跨窗复合」是要保住的性质。
- T 行锚 = 注册常数，不训头、损失掩码（ctx4b 先例：「T 行锚 = 链/恒等，L_anchor 对 T 行掩码，不消费」）。
- 本轮 `trans_anchor_stopgrad=True` 固定；放开 detach 是独立第二臂，不在本修改内。
- 不碰 `configs/z_gen/common.py`（归 huyuxuan，不可写）。
- 不改 `_trajectory_losses`、不删任何既有损失键或指标列。
- 新 split 口径警告须随数字一起引用：无 test 列（109/27/0）；val 的 8 个受试者全部与 train 重叠
  （旧 split 是严格 leave-subject-out）；新 split 的平凡地板尚未重算。
- §10/§11 的探针地板口径不同（V 侧 27 val 会话池、T 侧 124 会话池），绝对值不可互比，只比各自相对量。

## 这解决了用户原问题的哪一半

原问题两句：「需要一个稳健的姿态头设计，起码弥补我模型在评估上这一点的不足」
与「还是说不用解决这一点，更改指标就行」。

- **指标那一半**：07 改动 C 的 `WinDispMag` / `WinDispAngle`（已落地，复现手算
  V2M 54.7mm/13.9°、VT2M 52.4mm/13.8°、T2M 89.1mm/40.5°）给出两列窗内无锚读数——
  锚在窗内差分里代数消去。那是「不需要动模型就能诚实报」的部分。
- **模型那一半**：本修改让模型**自己产出那个常数**，于是「绝对位置」从协议外的 GT 输入
  变成模型的一路输出，`GlobalMPJPE` 不再是唯一口径。
  用户已指出「所有视觉模型都没有绝对位置输出，这在当前研究中不算空洞」——所以本修改的定位是
  **把一个本可从固定相机 + CLIFF `bbox_info` 读出的量（§10 实测 −56.3%）接出来**，
  不是去补一个公认的缺陷。
