# 修改 12：让 T 知道怎么走——状态/模式条件化（2026-11-05 立）

回答什么问题：**视觉给完初始条件之后，T 能不能“知道”自己正在怎么走？**
如果不能，缺的是哪一种输入：初始状态、运动模式，还是模式切换信号？

本文档不改主表模型，只给 AR2 线（相对读出 + 外部 ψ）的下一步设计。
配套阅读：[10_Cv5主线表与全族自锚化](10_Cv5主线表与全族自锚化.md)（主表与协议）、
[11_触觉表征整改与双足IMU接入](11_触觉表征整改与双足IMU接入.md)（触觉表征与传感器）。

---

## 0. 一句话结论

**当前 AR2M 的 T 行只输出相对增量（Δyaw、v_head），它看不到初始 ψ、看不到初始速度、也没有“当前是前走/后退/侧移/转向”的模式输入；真正知道起始情况的是网络外的组装层，不是 T。**
所以“视觉给初始条件 → T 接力”只在**航向**上成立（E9：cold-T 39.4° → 预热后 5.1°），
在**行进方向/运动模式**上没有成立——AR2M 的 T2M `WinDispAngle` 仍是 58.8°，比 Cv5 的 40.5° 还差。

要让 T“知道怎么走”，需要把**状态与模式显式做成网络输入**，而不是只放在后处理里。

## 1. 测量依据（全部为本轮已有产物）

### 1.1 触觉能读什么、不能读什么

| 量 | 压力可读性 | 证据 |
|---|---|---|
| 航向系前向速率（含前后符号） | **强** | 留一受试者 W=200，**−55.9%（7/7）** |
| 世界系 x/z 速度分量 | 弱 | −9.9% / −9.5% |

### 1.2 行进方向与身体朝向不是一个量

`gt_travel_vs_bodyfwd.py`（369 个位移 >2cm 的窗）：

```
GT 行进方向 vs GT 身体前向轴：中位 48.9° / 均值 47.4°
前向轴占优的窗占比：68.3%
```

有符号 course angle 分布（本轮补算，同一脚本口径）：

| 分位 | \|夹角\| |
|---|---|
| p10 | 3.5° |
| p25 | 9.4° |
| p50 | 51.3° |
| p75 | 104.8° |
| p90 | 172.4° |

累计：`<10° 25.7% / <15° 32.2% / <30° 42.3% / <45° 48.8% / <60° 51.5%`；
符号：**正 45.3% / 负 54.7%**；按会话中位从 **5.1°** 到 **173.2°**。

判读：

- 不是“所有动作都偏 48.9°”，约 1/4 的窗几乎对齐（<10°），这部分 T 的速率读数可以直接用；
- 但**符号几乎对半**，一个常数偏置会修好一半、毁掉另一半；
- 按会话差异极大（直走 ~5°、侧移 ~90°、接近反向 ~170°），所以正确形态是
  **模式选择 + 每模式偏置**，不是单一偏置。

### 1.3 初始条件只解决“从哪开始”

E9 视觉预热（现状.md §3）：

| 模型 | 臂 | RootOrientErr |
|---|---|---|
| AR2M | cold_T | **39.44°** |
| AR2M | V_to_T（预热 40 帧） | **35.54°**（学习增益，弱） |
| ARSS2 | VT_to_T | 20.94° |
| 固定增益 1 的声明协议 | 预热 40 帧 | **5.1°**（先导实验） |

- 航向：初始条件有效（39.4° → 5.1°），这是 E9 的基础；
- 方向：AR2M 的 T2M `WinDispAngle` 58.8° vs Cv5 40.5°（act8020），说明预热之后
  “往哪走”仍然没有解决。

### 1.4 T 的直接贡献是步态驱动，不是全局路径

从 E9 与方向列可以间接看出：T 能把模型“驱动起来”（速率、相位、接触），
但全局朝向/路径必须由外部状态给。本文档不再引用未定稿的单帧探针数字，
只用已入库的 E9 表与 `WinDispAngle` 作为依据。

## 2. 当前实现的缺口

AR2M 的结构是：

```
网络：T → (tilt/body, Δyaw, v_head)          # 只输出相对量
网外：ψ += Δyaw；p += Y(ψ)·v_head/FPS        # 状态只在组装层
```

问题：

1. **T 看不到 ψ**：初始朝向由视觉给，但没进网络；T 不知道“现在朝哪”，
   只能输出增量；
2. **T 看不到上一帧速度**：不知道当前是快走、慢走、侧移还是后退；
3. **没有模式通道**：前/后/左/右/转这些 course-angle 模式，网络里没有表示；
4. **模式切换不可检测**：初始条件只在 t=0 有效，序列中从直走变侧移时，
   T 没有任何信号告诉它“模式变了”。

注意：这不是要恢复被放弃的 AR 反馈支路。AR 失败的是**144 维全姿态反馈**
（teacher forcing 下学到低幅修正、自由生成塌缩）。这里要加的是**低维状态/模式 token**
（几个标量 + 一个模式 one-hot），零初始化、只影响 T 行，语义与 AR 反馈不同。

## 3. 方案：状态 token + 模式先验 + 切换检测

分三层，按成本从低到高；每层都可以独立验收。

### 3.1 层 A：状态 token（state token）

在 T 行 decoder query 上加一个**低维状态嵌入**：

```python
# s_t = [v_head_prev (3), |v_head_prev| (1), mode_embed (k), gait_phase (2)]
state_mlp = nn.Sequential(nn.Linear(3 + 1 + k + 2, d), nn.GELU(), nn.Linear(d, d))
# 零初始化末层；只加到 T 行（v_present == 0）的 root/part query
q_t = q_t + mask_t * state_mlp(s_t).view(B, 1, 1, d)
```

- `v_head_prev` 用上一窗/上一帧的**相对**速度，不用绝对 ψ，避免网络重新学绝对航向；
- `mode_embed` 是模式 one-hot/embedding（见 3.2）；
- `gait_phase` 可由压力/接触相位给（已有 `phase_gt` 监督线可参考）；
- 零初始化 + 只作用 T 行 ⇒ init 时 T 行与 AR2M 逐位相同，V/VT 不受影响；
- 该 token 是**网络输入**，与外部 ψ/p 的组装状态分开，不重复计航向。

### 3.2 层 B：模式先验（mode prior）

定义 M 个 course-angle 模式（数量可先取 4–6）：

```
m ∈ {前向 ~0°, 后向 ~180°, 左侧 ~+90°, 右侧 ~−90°, 转向}
travel_dir ≈ R(ψ + φ_m) · forward_axis
```

- `φ_m` 是每个模式的可学习/可声明偏置；
- 模式来源：
  - **切换时**：视觉分支最后 K 帧的预测速度方向 vs 预测朝向 → 初始模式；
  - **T 运行中**：压力特征分类器（见实验 P0）→ 模式后验；
- 模式 embedding 进 3.1 的 state token；`φ_m` 进组装层（`v_world = Y(ψ+φ_m)·[v_f,0,0]`）
  或作为 v_head 头的条件，二者选一，不重复。

关键：**模式是一个离散的中间量，不是最终方向**。这正好符合“自回归作用于中间量、
最终量事后组装”的原则：T 负责“怎么走”（模式 + 速率），世界方向由 ψ + φ_m 组装。

### 3.3 层 C：切换检测（switch detector）

序列中模式会变（直走→侧移、转身）。最小实现：

- 用压力窗口特征（左右脚力比、CoP 偏移、足底内外侧分布）训练一个**模式切换二分类器**；
- 或让 T 的 mode head 每帧输出后验，加 hysteresis/最小驻留时间防抖；
- 切换信号更新 3.1 的 mode token；ψ 不重置（航向连续）。

如果 P0 证明压力分不开模式，层 C 降级为“视觉切换时给一次模式，之后保持不变”，
只覆盖模式恒定的会话（约 1/4 的窗 <10°，加上部分侧移/后退会话），这是可接受的退路。

## 4. 参考哪些模型

| 参照 | 借什么 | 不借什么 |
|---|---|---|
| **E9 视觉预热** | 视觉初始化 ψ/p、切换协议 | 固定增益 1 的声明协议（只作 oracle 上界） |
| **AR2M** | 相对读出 Δyaw/v_head + 外部 ψ | 自由积分轨迹口径（Global 不可比） |
| **AR2MA** | 按行分支：V/VT 绝对，T 相对 | 未配平的航向损失（13–14× L_pose） |
| **Cv5RT** | 零初始化残差/适配器，保证 init 零税 | VT 触觉残差本身（那是融合，不是状态） |
| **Step2Motion** | 初始 global rotation 约定、heading-frame 轨迹 | 合成 IMU、100 帧窗、重叠携带 |
| **F2a / V3_4a** | 把航向从目标空间拆出 | 旧线数字与旧口径 |
| **11 文档双足 IMU** | yaw rate/速度的**直接观测**（层 C 的硬件解） | 阶段 B 的传感器成本（先做软件方案） |
| **T2M-GPT / MotionGPT** | 离散 motion token 做 AR 的思路 | 不把姿态 token 化（我们保持连续回归） |
| **HuMoR** | 低维 latent state 递推 | diffusion/优化推理 |
| **WHAM / GVHMR** | 视觉全局轨迹/朝向先验 | 尺度与数据口径（不并表） |

内部参照优先：E9、AR2M、AR2MA、Cv5RT 都是本项目已跑过的；外部模型只借“状态 token /
离散模式 / 低维递推”这三个范式，不借具体网络。

## 5. 实验顺序与判据（预注册）

### P0（零重训）：压力能否分出模式

- 数据：act8020 全部有位移窗；标签由 GT course angle 离散化（前/后/左/右/转）；
- 特征：纯压力（不含运动学量、不含接触标签）；
- 协议：留一受试者；
- 判据：
  1. 平衡准确率 > 1/M + 0.10（M=模式数），且混淆矩阵不是单类坍缩；
  2. 切换检测的召回/延迟可报（至少给出 F1 与中位延迟）；
  3. 如果 P0 失败，层 C 降级为“视觉一次给模式”，P1/P2 只覆盖模式恒定会话。

### P1（oracle 模式上界）：模式 token 值多少

- 模型：AR2M/AR2MA + state token，**模式用 GT（仅训练/上界，不作为交付）**；
- 判据：
  1. 模式恒定会话上 course-angle 误差（`WinDispAngle` 或逐窗 course error）下降 ≥30%；
  2. T2M PA/MPJPE 不劣于 AR2M（噪声内）；
  3. V/VT 主列不劣（状态 token 只作用 T 行，应零税）。

### P2（预测模式）：能否兑现

- 模式来源：视觉切换时给初始模式 + T/压力切换检测；
- 判据：
  1. 至少保留 P1 一半的 course-angle 收益；
  2. 无 GT 泄漏（模式来自 V/T，不读 GT course angle / GT 模式）；
  3. 遮挡档 `Δ(VT−V)` 不被破坏。

### P3（可选）：双足 IMU

- 若 P0 失败，按 11 文档阶段 B 接入双足 IMU 的 yaw rate/速度，直接给层 A 的 `v_head_prev`
  与层 C 的切换信号；
- 判据：course-angle 误差与 RootOrientationDrift 同时下降。

成本：P0 零重训（CPU/分钟级）；P1/P2 各 1 次训练；P3 取决于传感器。

## 6. 边界与风险

- **不恢复全姿态反馈**：state token 是低维（≤16 维）、零初始化、只作用 T 行；
  与 AR/AR2 的 144 维反馈不同。若实现后发现 T 行退化为“复制上一帧”，立即停。
- **不把绝对 ψ 喂进网络**：只喂相对速度/模式/相位；ψ 继续在网外积分，
  避免网络重新学绝对航向、也避免与外部状态重复计。
- **模式标签只用于训练**：推理时模式必须来自 V/T/IMU，不能读 GT；
  oracle 臂要明确标注为“上界”，不进主表。
- **模式常数偏置不成立**：course angle 符号正负 45/55、按会话 5°–173°，
  必须模式化；单偏置会修一半毁一半。
- **不改变主表口径**：本文档的模型属于 AR2 线（自由积分、0 锚），
  与 Cv5 主表不并表；主表仍是 SD2/Dv1。
- **新 split 口径**：act8020 val 与 train 受试者重叠；模式分类的泛化必须用
  old split 或四折 LSO 复核。

## 7. 与现有路线的关系

```
Cv5 主表线（SD2 / Dv1）         → 不引入状态 token（窗独立，无跨窗状态）
AR2 线（AR2M / AR2MA）          → 本文档的载体：相对读出 + 外部 ψ，天然需要“怎么走”
11 触觉表征/IMU                 → 层 A/C 的传感器与表征供给
12 本文档                       → 层 A/B/C 的软件实现与判据
```

判定标准很简单：**如果 P1 的 oracle 模式都不能让 course-angle 明显下降，说明问题不在
“T 不知道模式”，而在“模式本身不可由 T 维持”，那就只剩 IMU/视觉切换一条路。**
