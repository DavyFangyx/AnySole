# 修改 02：接缝归因与重叠拼接推理（零重训）

## 一句话目标

报表上 T2M 的 Jitter_pred 1784 里，**91% 长在 20 帧非重叠窗口的拼接处**，窗口内部运动本来就是光滑的（Cv5 内部 jerk 217 vs GT 130）。本修改把拼接从「硬接」改成「重叠混合」，在**不重训、不增加 GT 泄漏**的前提下把这部分拿掉。

## 为什么（现有证据）

`anysole/utils/eval_protocol.py:40-43` 明确：eval 窗口非重叠（`stride == window_length`），会话预测 = 各窗**直接拼接**（标准路径见 `:960` 的 `pred_pose.reshape(-1, ...)`）。窗 w 末帧与窗 w+1 首帧之间没有任何连续性机制。

主会话 2026-11-03 实测（test，按窗内帧号拆 jerk）：

```
窗内帧号:         0     1     2     3  ...  16    17    18    19
GT              126   117   118   123  ... 123   123   122   129
V7_Cv5        17028 16871   251   251  ... 246   299   271   259
V7_AR2M        9418  9357   195   380  ... 498   417   378   315
V3_Bv1         7066  6791   989   972  ...2524   880   986  1037
```

接缝（窗内帧号 {18,19,0,1}，占 20% 的帧）吃掉的 Jitter 份额：Cv5 **91%**、ARSS2 93%、AR2M 76%、AR2R 74%、V3_Bv1 35%；GT 19%（= 均匀）。

同时 **PA 剖面是平的**（Cv5 88→94，全帧 89.4 / 去接缝 89.2）——接缝不吃姿态分。所以抖动与姿态精度是两个解耦的失效，本修改只动前者。

对等性参照：外部基线 Step2Motion 的 Jitter_pred 260（我方 1784），它用 100 帧窗 + 重叠携带。即当前对比里混入了**拼接策略**这一因素，不是纯粹的生成器质量差异。

## 要做什么

### 阶段 A：把归因固化为可复算产物（必做）

用 01 的 `e0_window_profile.py` 对现役全部 T2M/V2M/VT2M 行出剖面表，落 `results_display/Etest/E0_ReferenceFloors/Full_Table2_E0_WindowProfile.csv`。若 01 尚未完成，本修改先自带等价实现，后续合并。

### 阶段 B：重叠拼接推理（主体）

新增**声明口径的协议变体**，不替换现协议：

1. **数据层**：`anysole/eval.py:728` 已有 `stride=(tw // 2) if (... or v7_ctx) else None` 的先例。新增命令行开关 `--overlap-stride N`（N ∈ [1, tw)，默认 None = 现协议），把 `stride` 透传给 `AnySoleDataset`。
2. **协议层**：`anysole/utils/eval_protocol.py:1512-1517` 现在遇到重叠 stride 会**跳过自己**。改为：重叠 stride 下走新的组装分支，而不是跳过。
3. **组装规则**：对每个会话帧 t，收集覆盖它的所有窗口预测，按**三角权重**（窗中心权重 1、窗边缘权重 →0）加权平均。
   - 旋转通道（6D）**不得直接线性平均**：先按权重做加权平均再正交化投影回 SO(3)（复用 `anysole/utils/geometry.py` 现有的 6D→rotmat→6D 往返与正交化助手，不自写）。
   - 速度/平移通道按权重线性平均。
4. **GT 泄漏硬约束（公平性前提）**：现协议每窗用 GT `trans_anchor`（帧 left−1）锚定平移，是唯一的推理侧泄漏点。重叠窗会按 stride 成比例增加锚点数量，**这是不可接受的**。要求：
   - 锚点网格**保持原非重叠网格**（仅在 `w*tw` 处取锚），重叠窗继承其所属 tile 的锚；
   - 产物里登记 `n_gt_anchors_used`，必须与现协议**逐位相同**；
   - AR2 族自由积分轨迹（无每窗 GT 锚）不受此约束，但同样要登记。
5. **扫描**：stride ∈ {20（= 现协议，对照）, 10, 5, 2}，对 `V7_Cv5_s1` 与 `V7_Cv5AR2M_s1` 两个模型、T2M/V2M/VT2M 三条件。推理成本按 tw/stride 线性增长，stride=2 约 10×；先跑 stride=10 与 5，2 作为可选上限点。

### 阶段 C（仅当 B 受阻时的退路）

若 B 的锚点约束与实现冲突无法在本轮解决，退到**导出后接缝混合**：对已落盘 npz 在接缝两侧各 2 帧做声明过的加权过渡。这是后处理，必须在表注里写明「post-hoc seam blending」，不得混入主口径。退到 C 需要在回报里明确说明受阻点。

## 验收判据（预注册）

对 `V7_Cv5_s1` T2M，stride=10 相对现协议：

| 项 | 要求 |
|---|---|
| Jitter_pred | 显著下降（预期落到 400–700 量级；只要 < 900 即判有效） |
| 接缝占总量 | 从 91% 回落到 ≤ 40% |
| PA-MPJPE | 变化在 **±1.0 mm** 内（超出说明混合损伤了姿态，报告并停） |
| GroundPen / FootSliding | 不升高超过 10% |
| `n_gt_anchors_used` | 与现协议逐位相同 |
| stride=20 分支 | 走新代码路径时，十指标与现协议**逐位一致**（等价性自检） |

最后一项是硬门：stride=20 不能逐位复现，说明新分支改变了口径，先修代码再出数。

## 边界

- 不改模型、不改训练、不重训、不生成新 ckpt。
- 不替换现协议默认值；`--overlap-stride` 不传时行为逐位不变（遵守「conf 发射保持默认值」）。
- 不把重叠口径的数字直接写进 E2 主表——先作为声明口径的对照表出，是否升为主口径由用户裁定。
- 不动 `configs/z_gen/common.py`（归 huyuxuan 不可写）；需要 conf 时手工落盘到 `configs/queue/`。
- 评估用卡限 cuda:4/5/6/7。
