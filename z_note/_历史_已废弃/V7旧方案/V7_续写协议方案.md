# V7 续写协议方案（2026-10-31 设计稿，待裁定）

背景与范围
- 现状：tw20_st20 非重叠滑窗，V/T/VT 三条件窗边界接缝每 0.5s（20 帧/40Hz）一次；
  T2M 窗间航向差 |Δ|<15° 占比 63%（VT 94.6%，2026-10-29 实测），偏航/横滚窗界跳变。
- 目标：移植 Step2Motion 的「重叠上下文 + 以上一窗为条件」，不移植扩散 inpainting。
- 边界（用户已裁定）：触觉不提供世界系航向信息，首窗航向仍由模型先验给出——
  续写修「窗间连续」，不修「整体绝对偏移」。评估 PA 对齐兜底，部署外部 IMU 兜底。

## §1 续写上下文 ctx 定义

- ctx = 窗首帧根状态，10 维：
  根 6D（pose 归一化空间，POSE_DIM[0:6]）+ 根速度 3D（v_hat 空间，vel_gt 口径）
  + 有效标志 1 维。
- 训练（teacher forcing）：ctx = GT 窗首帧根状态，零新增裁剪（pose_gt[0,:6]、
  vel_gt[0,:3] 均在现窗口内）；会话首窗（left==0）→ 全零 + flag 0（自然频率 ≈
  每会话一次，与评估首窗频率同分布，无需额外掩码）。
- 评估：stride = tw//2 重叠窗，链式 ctx = 上一窗预测在其内部帧 half 处（= 本窗
  窗首帧）的根状态；valid_windows 跳窗（fake 帧）时 ctx 复位为 flag 0。
- 位置连续：评估轨迹锚沿用 trans_anchor（与现协议同口径，PA 对齐不受影响）；
  infer/显示用预测锚缝合（stitch_anchor 机制，infer.py:463 已有）。

## §2 结构侧（输入多一路，输出零改动）

- 关键修正（与 10-29 对话草图的差异）：「拼进现有 token 序列尾部」不能只拼一路——
  解码器 V/T 两分支输出各乘 per-sample 存在掩码（model_v7.py:105/120），拼 m_v
  在 T2M 被杀、拼 m_t 在 V2M 被杀。续写上下文是模型自己的输出，必须三条件全存活。
- 落法：ctx 过 Linear(10→d) 得 1 个 token，**同时拼进 m_v 与 m_t 尾部**
  （model_v7.py AnySoleModelV7.forward，v_temporal/t_temporal 之后）——六层解码器
  现有 cross-attention 自然读到；任一条件至少一路存活；VT 双读由模型自学习。
- 解码器层、门控（含 T/LR/TLR/Q）、V/T 编码器、接触头、运动头、FK 全部不动；
  新增参数 = 一个 Linear(10→512)。
- ctx=None（旧模型/旧 ckpt）：forward 逐位不变，全兼容。

## §3 训练侧

- 训练窗 stride 保持 tw（非重叠）——重叠是评估协议，不进训练分布；
  训练改动 = 数据集多一列 ctx + forward 多一参数。
- dataset 新参数 v7_ctx（默认关）：__getitem__ 增 ctx 键；关时 item 逐位不变
  （旧模型评估逐位不变纪律）。
- 损失不变：ctx 经姿态损失教师强制（模型学到「窗首根状态 ≈ ctx」，评估时 ctx 是
  自身预测 → 链式复制 → 连续），无新损失项。

## §4 评估侧

- eval.py：dataset stride=tw//2（现 704 行 pos_mode 专用 → 加 v7_ctx 条件）；
  读 ckpt 结构键 v7_ctx 决定。
- _evaluate_config 增续写分支：按会话逐窗链式生成（不整批），crossfade 组装
  整会话 pred_pose/pred_trans → 复用现有装配与 _session_metrics——十指标口径
  不变，数字与现协议可比。
- crossfade：同时间帧线性淡化，淡化长度 = 重叠区半窗（10 帧）；
  组装用各窗原始预测，链式 ctx 链用原始预测（不消费淡化输出）。
- 现有 _pack_motion_export 的「仅真正重叠才淡化」逻辑（eval.py:82）同源复用。
- 接缝诊断：独立脚本统计窗界帧 |Δyaw|/|Δroll|（不并入协议）——
  判据：T2M |Δ|<15° 占比 63% → 90%+ 级；jitter/seam 指标同步看。
