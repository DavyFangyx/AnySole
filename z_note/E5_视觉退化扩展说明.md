## 2 实现设计

### 2.1 曝光异常

- 入口：`anysole/data/extract_hrnet.py`。新增 `--exposure-gain G`（float），与 `--occlude-lower` 互斥。
- 作用位置：`read_rgb` 之后、`process_image` 之前（约 205–206 行，与 `occlude_lower_strip` 同位）。整帧作用，不依赖 bbox。
- 公式：`out = np.clip(rgb.astype(np.float32) * G, 0, 255).astype(np.uint8)`。G=1.0 为恒等。
- bbox 与 bbox_info 保持干净（沿用 occ 口径，直接读现有 `bbox.npy`）。
- 档位：欠曝 G = 0.5 / 0.2 / 0.05，过曝 G = 2 / 4 / 8，共 6 档。先各导一个会话的一帧 jpg 目视确认「轻 → 近乎死透」，档位不合适就改 G，不改机制。
- 落盘目录：`hrnet/cam3_exp_g{round(G*100):04d}`，即 g0005 / g0020 / g0050 / g0200 / g0400 / g0800。目录命名函数仿 `occlusion_cache_dirname`（65–68 行），`resolve_roots`（71–85 行）加一支分派。
- provenance：`parameters` 里记录 `exposure_gain`（仿 259–262 行记录 occlude_lower 的写法）。
- 范围：先 `--split test`（S13+S14，36 会话）。若评估同时遍历 val，则补 `--split val`。先实测 1 个会话的 HRNet 用时，再决定多档并行，并发 ≤4 卡。

### 2.2 连续断流

- 入口：新脚本 `anysole/data/make_gap_cache.py`。输入现成 `hrnet/cam3` 缓存，不碰图像、不跑 HRNet。
- 退化方式：冻结。断流帧取最近一个活帧的整条 2051 维特征（含 bbox_info 3 维），即整路视觉冻结。选冻结不选置零：置零接近训练期 T 行里 V 被置零的状态，模型可识别；冻结是看起来合法的陈旧证据，更接近真实断流。
- 断流模式：周期 C=100 帧（2.5 s）。每个周期内最后 round(ρ·C) 帧为断流，其余为活帧。ρ=10/20/40/60/80% 对应断流长度 10/20/40/60/80 帧（0.25 / 0.5 / 1 / 1.5 / 2 s，40 Hz）。
- 相位：每个会话用 `np.random.default_rng((seed, 会话号哈希))` 取一个 0..C−1 的相位偏移，避免与 20 帧窗口边界对齐；第 0 帧强制为活帧，保证有锚点。seed 固定为 0。
- 会话列表：复用 `extract_hrnet.split_session_ids`（96 行），范围同曝光轴。
- 落盘目录：`hrnet/cam3_gap_r{ρ%:03d}`，即 r010 / r020 / r040 / r060 / r080，文件布局与 cam3 一致（`<session>.pt`）。
- provenance sidecar：建议同样写（`kind=stream_gap`，参数 rho / cycle / seed）。`dataset.py` 里没有 provenance 校验，写它只为与缓存农场口径一致。
- 与 E7 的区别：本实验输入固定为 VT，模型不知道退化发生。E7 是已知可用性切换，两者在 4.3 里用一句话区分。

## 5 验收门（完成后我逐项检查）

- G1 缓存结构：会话数 = 所评 split 全集；shape = (n, 2051) 且 n 与 cam3 一致；每个新目录用 `occ_mix.check_dual_cache(session, occ_root=新目录)` 过闸（形状相等、特征非全同）。
- G2 曝光机制：特征末 3 维（bbox_info）与 cam3 逐位相同；G=1.0 对 1 个会话重抽取，与 cam3 缓存最大绝对差 ≈ 0，排除重抽取本身不确定。
- G3 断流机制：ρ=0 的输出与 cam3 逐位相同；活帧逐位等于 cam3；冻结帧逐位等于其锚点帧；冻结帧占比 = ρ（±1%）。
- G4 yaml：与模板 diff 只有 `cache_root` 一行。
- G5 操纵检查：极档（G=0.05 / G=8 / ρ=80%）的 V2M 明显劣于干净，且整体随严重度上升（不要求逐档严格单调）。否则说明退化没有送到模型，先查缓存路径。
- G6 对账：干净行与下肢截断五行对上 `Full_Table1_E5_Occlusion.csv`；总表每格都有 Full 表里的绝对值可查。

## 6 论文口径与已知边界

- 遮挡的实际协议是 bbox 底部整幅涂黑（`--occlude-fill black`），论文须按此描述为合成下肢遮挡，不写成实物遮挡。审稿人可从代码与附录核对协议，与实际不符的风险远大于补一个对照的成本。
- 填充方式对照：`--occlude-fill blur` 对 occ 040 / 060 各在 test 上跑一遍，作补充材料，说明结论不依赖黑块。
- 曝光轴：bbox 来自干净画面，V 的检测不受曝光影响，对 VT 偏保守，声明一句即可。
- 判据沿用 `实验计划.md` 4.3：看 VT 与 V 的交叉点及交叉后的增益斜率，不要求全档单调，也不预设三条轴同向。各轴结果如实呈现。
- 触觉兑现的是下肢、根轨迹与足地物理，不是全身 PA。子图按此选指标，PA-MPJPE 作整体参照。
