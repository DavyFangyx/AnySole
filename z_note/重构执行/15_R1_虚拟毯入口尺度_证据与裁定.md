## ① 结论

**建议方案：D —— 入口张量 (192, 96)（虚拟毯 320×120 直接 bilinear 到 192×96，长轴 ×2 分辨率）；待用户确认。**

理由（全部可复算，数值见 ③）：

1. **现行方案 A 的入口不是"同一物理场换分辨率"，而是入口像素被放大 2×**：长轴入口像素 41.667mm（原生 20.833mm），足印像素面积 **44.237 px² vs 原生 88.474 px² = 0.500000（精确一半）**；各向异性压缩 **2.6667 vs 原生 1.3333（恰好 2.00×）**，且足印在入口的像素纵横比从原生 1.50（沿行伸长）反转为 0.75（沿列伸长）。
2. **A 还附带一个纯信息丢失项（非尺度问题）**：320→96 的 bilinear 是 2×2 定点采样、步长 3.333，长轴 320 行中 **128 行（40.0%）永不参与入口任何像素**（解析 + one-hot 基双重验证）。S5091 实测：有压帧的入口非零像素 A 20.09 / B 24.62（**+22.5%**）。
3. **方案 B 按其字面描述达不到"与原生一致"**：只要入口是 96×96 且覆盖 4m，长轴入口像素必然是 4.0/96 = 41.667mm，足印必然是 5.76×7.68 px —— 与 A **逐项相同**。B 唯一真实收益是消除 40% 丢行（抗混叠）。B 的题面陈述（"入口像素物理尺寸与原生完全一致（2.083cm/px）、足印恢复 11.5×7.7px"）在 96×96 入口下**算术上不可能同时成立**（96 像素覆盖 4m 与覆盖 2m 互斥）。**这一点必须在拍板前更正，否则会造成"尺度问题已修复"的错误结论。**
4. **要把入口像素语义恢复成原生，只有两条路**：缩短视场（方案 C：2m 滑窗，代价高、需窗口位置信号）或提高入口分辨率（方案 D：192×96）。D 让 320×120→192×96 的降采样倍率（长 **1.6667**、宽 **1.25**）与原生 160×120→96×96 **完全一致**，于是入口像素尺寸、源像素/入口像素、足印像素、各向异性、以及 **每一层特征图的物理格距**（conv1→layer4，D：4.21/4.26/8.51/16.67/33.33 cm vs 原生：4.26/4.35/8.70/16.67/33.33 cm，比值 0.98–1.00）全部与原生对齐；唯一差异是**长轴视场 4m vs 2m**，这正是用户 09-28 裁定的虚拟毯本意。
5. **D 的代价可测且有限**：入口 H 96→192 只改 `image_pressure.py:130` 一行；模型结构零改动（resnet18 `AdaptiveAvgPool2d((1,1))` + `fc=Linear(512,2048)` 吸收任意 H×W，`FRAPPE.forward` 的 height/width 是运行时读取，GRU `input_size=2048` 不变，参数不变：触觉分支 12.218M / 全模型 200.31M）；实测前向 **触觉分支 +119.7%**（1176.8→2585.9 ms/320 图）、**整模型 +62.3%**（2300.2→3733.8 ms/步，B=16,T=20，CPU）。不需重产任何数据（140 session 落盘不动），V3 判据数值不受影响（③e）。
6. **若用户坚持"入口 96×96 不变"的既有裁定**：退守方案 B，但必须按 **消费端**实现（磁盘保持 (T,320,120)，在 `_resize_pressure` 内先 320×120→160×120 area 降采样再 bilinear 96×96），并**明确记录"入口尺度仍为原生的一半"**。题面所述"改 adapter 落盘侧、消费端零改动"的 B 变体**不可行**（见 ④ 更正栏：会击穿 `image_pressure.py:177-180` 与 `test_virtual_carpet.py:390-399`，并把 V3 的 ±3px 窗口物理尺寸从 7.5cm 变成 15cm）。

**并行提示（优先于本裁定）**：虚拟毯的**世界锚点**目前把行走区域切掉了一半 —— 全量 140 session 中 **28,325/52,612 帧（53.8%）整幅毯为空**、**30/140 session 全空**；仅 11.4% 的 session 行走范围完全落在毯内（细节与数值见 ⑤-1）。该问题是数据可用性问题，量级远超入口尺度差异，建议独立裁定。

> 拍板权归用户。**待用户确认**：入口尺寸取 (192,96)（方案 D）还是维持 (96,96)（方案 A/B）；以及锚点问题是否同批裁定。

### e. ±3px 判据与 resize 无关（已核实）

- 训练期接触监督与毯无关：`contact.npy` = soft-f6 (T,10)，由 48 格鞋垫直接产出（2.4），因此"接触标签"口径也不受 resize 影响。

## ⑤ 风险陈述

### 1.（材料性，优先于本裁定）世界锚点导致过半帧触觉为空 —— 建议独立裁定

实测（全量 140 session，`/tmp/r1-scratch/r1_usage.py`、`r1_span.py`）：

| 量 | 实测 |
| --- | --- |
| 整幅毯为空的帧 | **28,325 / 52,612 = 53.8%**（与 adapter 自身 artifact.json 统计逐项吻合：`frames_any_paint` 合计 24,287 + `frames_out_of_bounds` 合计 28,325 = 52,612） |
| 全空 session（每帧皆空） | **30 / 140**（如 S5061/S5062/S5063/S5071/S5072，`painted_px = 0`，`frames_out_of_bounds` = 帧数） |
| 每 session 长轴实际使用格 | 均值 47.8 格（59.8cm）/ 中位 17.0 格（**21.2cm**），毯长 400cm ⇒ **均值 14.9%** |
| 每 session 宽轴实际使用格 | 均值 14.3 格（17.9cm），毯宽 150cm ⇒ 12.0% |
| 行走范围完全落在毯内 y∈(-4,0] 的 session | **11.4%** |
| 足部中心实际世界范围 | x ∈ [-0.27, +0.23] m，y ∈ [-2.50, +2.36] m |
| 当前毯矩形 | x ∈ [0.006, 1.494] m，y ∈ [-3.994, -0.006] m |

根因：毯以**世界原点为角点**只覆盖 y ≤ 0 半平面，而受试者行走以世界原点为中心（y 跨 ±2.4m）——锚点偏移了半个走廊。后果：① 模型在一半样本上收到的触觉输入恒为 0；② 长轴 4m 中约 85% 未被使用；③ 这是"4m 全景"当前名不副实的直接原因。**注意**：即使修正锚点，仍有 10% 的 session 行走跨度 > 4m（最大 4.57m）、宽轴最大跨度 1.94m > 1.5m，因此越界不能完全消除（V1 裁定已接受越界不标记）。**方案 A/B/D 全部继承该问题；只有方案 C 能消除它。** 建议在入口尺度拍板的同时另行裁定锚点（本代理未做任何改动）。

### 2. "从零训练"前提的事实修正：触觉分支是 ImageNet 初始化

`lib/model/FRAPPE.py:129` 为 `torchvision.models.resnet18(pretrained=True)`，且本机缓存存在 `~/.cache/torch/hub/checkpoints/resnet18-f37072fd.pth`，实测在 `touch_gait`（torchvision 0.19.0）离线可加载成功（warning 仅"pretrained 参数已弃用"）。被替换的 `conv1` 为随机初始化（权重 std 0.1297），但 `layer1..layer4` 为 ImageNet 权重（std 0.0534）。故"无预训练权重迁移"对**图像流**与**任务头**成立，对**触觉 resnet18 主干不成立**。影响：① 论文/报告口径需修正；② 无网络机器上训练会失败或行为不一致（可复现性风险）；③ 对 R1 判断影响有限（conv1 随机、全程微调），但"入口尺度改变会影响 ImageNet 特征响应"这一论据因此不宜被当作决定性理由。**建议独立登记（超 R1 范围）。**

### 3. 存在旧版 MotionPRO checkpoint（与题面"全仓无已训 checkpoint"不符）

`results/baselines/MotionPRO/checkpoints/imagepressure2smpl/init/5e-05/imagepressure2smpl_best.pth`（09-22 19:26，epoch 31）与 `..._999.pth`（09-23 03:07）；同目录 `metrics/test_comparison.json`、`logs/test_frappe/2026-09-24_*`。其 hydra 配置 `logs/train_frappe/2026-09-22_19-10-23/.hydra/config.yaml` 显示 `seq_root: workspace://derived/MotionPRO/sequences/cam3` + `contact_method: tactile_abs` —— 即 **T1 虚拟毯之前的旧数据链**（旧 derived 树现已不存在；`workspace://` 在 `AnysoleWorkspace/tool/workspace.py:53` 已被显式拒绝）。该 ckpt 的入口是旧 160×120 鞋垫栅格 → **不能用于 adapter_v1 数据的任何对比或续训**，应归档；但它确实存在，故"全仓无 MotionPRO 已训 checkpoint"的表述需更正（不影响 R1 结论：无论选 A/B/C/D，模型都必须在新数据上重训）。

### 4. 各方案专属风险

- **A（现状）**：足印有效像素减半；长轴每层特征格距 2.00× 原生；conv1（stride2）后足印仅剩 **2.88×3.84 格**（原生 5.76×3.84），足长方向的鞋跟→前掌结构在最早层即被压到不足 3 格；40% 源行不参与 ⇒ 同一物理足印随亚像素相位产生系统性不同的入口张量（**残余噪声**），而压力入口侧**无任何数据增强**（2.3）可平摊该噪声。
- **B**：如按题面理解"已与原生一致"会形成错误结论（①-3 / ④）；实现必须走消费端，否则打破两处断言并使 V3 归档数值失效。
- **C**：见 ④ 末段（窗口中心信号 + 绝对位置线索丢失 + 时间抖动 + 新验证），且需改动"96×96 入口"之外的数据/模型链路，超出当前 T1 已收口范围。
- **D**：与 11 号文档"模型入口 bilinear 96×96 不变"的既有裁定冲突（需用户改判）；训练前向 +62.3%（CPU 实测，GPU 上比例未测）；入口张量形状变化会传导到任何按 96×96 写死的下游检查（当前 grep 显示只有 `image_pressure.py:130` 一处）；在锚点未修正前，D 增加的像素有约一半落在空白区域（收益被锚点问题稀释）。
- **共同风险**：本裁定的全部数值基于 `Baselines/MotionPRO` 当前代码与 `adapter_v1` 已落盘的 140 session；若后续重产数据或改动毯格距，③④ 需重算。
