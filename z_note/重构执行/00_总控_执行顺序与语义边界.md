# AnysoleWorkspace 重构执行总控

> 用途：分发给 6 个工作 Agent，统一执行顺序、语义边界、写入范围与交付格式。  
> 仓库根：`/data/fangyuxuan/projects/gait`  
> 最终验收：主 Agent（不由工作 Agent 自行宣布整体完成）。

## 1. 总目标

将当前以 `AnysoleWorkspace/derived/MotionPRO/sequences` 为事实中心的历史结构，重构为以采集事实和明确产物契约为中心的单向依赖：

```text
raw → protocol → shared → model_inputs/<model> → work → results → results_display
```

本轮不是对基线算法做“更好的统一”，而是恢复各基线的原生契约，只统一：

- session 身份、split 与 eligibility；
- frame id、视觉时间、动捕时间、valid/fake；
- 源 RGB、源压力、源 BVH/SMPL 及标定的可追溯性；
- 正式预测的输出位置与公共评估入口。

## 2. 不可突破的语义边界

1. 禁止为了跨模型“统一”而替换基线的训练 GT、loss、augmentation、归一化、输入排列或输出含义。唯一已批准例外是明确命名的 `MotionPRO-InsoleAdapted`：保留模型架构，采用鞋垫 dual-sole raster 和其私有四档 soft-f6 脚损失权重。
2. 基线必须优先对齐官方/上游代码契约，不得优先对齐 AnySole 的语义。
3. 上游原生缺陷可以记录，但不得在正式 baseline 中静默修复。需要修正时必须另建 `<Model>-corrected`。
4. `shared/facts` 只保存客观事实；多模型共用的确定转换放入版本化 `shared/representations`；前端模型产物放入 `shared/frontends`。
5. `model_inputs/A` 不得读取 `model_inputs/B`。
6. `AnysoleWorkspace/tool` 不得 import `results_display`。
7. 正式 checkpoint、prediction、metric 只能写入 `results/`；`results_display/` 只做展示和比较。
8. 未通过主 Agent 最终验收前，任何工作 Agent 不得删除旧数据、旧 checkpoint 或旧结果。

## 2.1 原始触觉唯一来源与 D_Test4 冻结裁定

当前 D_Test4 中出现的多种“硬件结构”并不是四份相互独立采集的原始数据。它们有且只有一个物理采集源：

```text
PressureWasher 最终 fake_marked session
├── pressure_left.csv   # 数值列 1..48，左脚 4×12
└── pressure_right.csv  # 数值列 1..48，右脚 4×12
```

经公共时间轴对齐后，提升为：

```text
shared/facts/sessions/cam3/<date>/<subject>/<session>/pressure_48.npz
├── frame_id
├── left48   # (T,48) == (T,4,12)
└── right48  # (T,48) == (T,4,12)
```

之后由各模型 adapter **独立地**从同一物理源生成自己的原生输入：

| 消费方 | 独立适配产物 | 来源链 |
| --- | --- | --- |
| AnySole | 左/右脚 48 格，及自身物理 token | `shared pressure_48 → AnySole adapter` |
| MotionPRO-InsoleAdapted | 当前固定左右块 dual-sole raster，模型入口为 96×96 | `shared facts pressure_48 → MotionPRO adapter` |
| Step2Motion | 16 通道/脚，heel8 + toe8 | `shared facts pressure_48 → Step2Motion pooler` |
| pressure_toolkit / FPP-Net | 共用一份版本化 31×11/脚 MMVP insole | `shared facts pressure_48 → shared representations/mmvp_31x11` |

注意：pressure_toolkit 和 FPP-Net 使用相同的 MMVP 硬件布局契约，因此只生成一份公共 `shared/representations/tactile/mmvp_31x11/<version>`，两者共同只读，不再复制两棵相同数据。

用户已通过肉眼审计确认 D_Test4 的 4×12→96×96、16 通道和 31×11 转换结果正确。因此本轮裁定为：

- Step2Motion 和 MMVP 转换几何/池化已冻结，不重新设计；MotionPRO 保留当前固定左右块，但明确重命名为鞋垫 `dual-sole raster`，不再宣称为压力地毯；
- 本轮只修正输入来源和目录所有权：不得再从 MotionPRO `pressure.npz` 裁回 4×12 作为公共中转；
- D_Test4 改为纯只读审计端，不再 subprocess 生产模型训练/优化输入；
- D_Test4 应展示每个产物的 raw source hash、shared artifact hash、adapter/version 和模型私有落点。

MotionPRO-InsoleAdapted 单独使用四档软 `f6_soft={0.05,0.30,0.70,0.95}` 作为左右脚 `loss_foot` 权重。该软标签是 MotionPRO 私有适配产物：

- 不修改 AnySole 当前已二值化的 `f6_soft.npy`；
- 不供 FPP-Net 使用；
- 必须在 MotionPRO artifact 中记录四档值、生成版本和语义。

MotionPRO 执行分两阶段：第一阶段只生成 dual-sole raster 与私有 soft-f6 审计产物；用户确认后才允许全量生成和训练。

## 2.2 唯一受试者 mask 与单人前端契约

用户已提供外部只读人体 mask 数据：

```text
/data/lizhe/projects/Tactile/3_Result/processed/rgb_human_masks/<session>/
├── masks_index.csv
├── segmentation_manifest.json
├── failures.csv
└── <camera>/<image_stem>.png
```

该数据由 SAM3.1 生成，每帧 mask 只包含受试者，即使 RGB 背景中存在旁观者也不纳入 mask。只读实测结果：

- canonical 140 session 全部存在 `masks_index.csv`；
- shared cam3 共 52,612 帧；
- 按 `visual_time_s` 最近邻匹配时，52,611 帧误差 ≤13ms，全部帧误差 ≤20ms；
- 无缺失 mask 文件。

固定契约：

1. 外部 mask 目录只读，workspace 不复制、覆盖或重生成这些 mask。
2. 在 `shared/frontends/human_masks/sam31/` 建立版本化索引/provenance。
3. 以 `session + camera=3 + visual_time_s` 匹配 shared frame，容差上限 20ms；不以排序位置或当前文件名猜测。
4. CSV 中部分旧记录为 `skipped_existing` 且 bbox 为零，因此 bbox 统一从实际二值 mask 重算；CSV bbox 只作审计。
5. mask 文件缺失、空 mask 或时间误差 >20ms 时，该帧标记 invalid，禁止回退到全景深度、全图 bbox 或多人检测行。
6. pressure_toolkit 的 depth mask 使用 `human_mask ∩ valid_depth ∩ [0.4m,5m]`。
7. CLIFF 使用 mask 重算的唯一受试者 bbox，每个 canonical frame 恰好生成一行 pose/betas。

这是正确输入契约的恢复，不是对基线模型结构或算法的优化。

## 4. 执行 DAG

### Wave 0：全员预检

每个 Agent 必须先执行只读检查：

```bash
pwd
git status --short
git diff --stat
```

必须在交付报告中列出：

- 开始时已存在的用户改动；
- 本 Agent 预计写入的文件；
- 与其他 Agent 可能冲突的文件。

### Wave 1：Agent A

Agent A 先建立新底座，但不删除旧 `derived/`。完成后由主 Agent 检查：

- 新路径解析可用；
- manifest 不依赖模型私有目录；
- split 只读且 92/12/36；
- shared facts/representations/frontends schema 已冻结；
- B–F 可在不修改公共文件的情况下工作。

### Wave 2：Agent B–F 并行

B–F 只修改自己的模型代码、私有 adapter 和模型测试。共享文档的修改建议写入交付报告，不直接修改共享文档。

### Wave 3：Agent A 文档收口

待 B–F 交付后，Agent A 根据实际完成情况统一更新：

- `AnysoleWorkspace/README.md`；
- 数据构建命令顺序；
- 公共路径和 artifact 契约；
- doctor/readiness 检查。

### Wave 4：主 Agent 联合验收

按 `07_主Agent_联合验收与清理.md` 执行。不通过时按文件所有权定向返工，不由主 Agent 直接猜测性修补。

## 7. 统一停止条件

遇到以下任一情况，Agent 必须停止扩大改动，以 `partial` 或 `blocked` 交付：

- 需要修改模型结构/loss/augmentation 才能继续；
- 需要用其他模型的私有产物作为数据源；
- 无法区分上游原生行为和本地适配行为；
- 发现用户改动与本任务重叠，且无法无损合并；
- 必须删除/覆盖大量数据才能验证；
- 公共 schema 需要变更，但 Agent A 尚未确认。
