### 4.4 顶点/区域面

- 受影响的 **3/96** 右脚顶点（SMPL 6653/6661/6701，接触数组索引 **12/15/30**）= 顶点 BCE 192 维中的 **3 维（1.56%）**。这 3 个顶点**没有**部分污染（`insole2smplR.npy` 中它们的格点全部来自该源通道 → 0 个"部分驱动"顶点），污染面是**封闭**的：不会渗到别的顶点。
- 顶点层面表现为"孤立正例"：随附 GT 的 15859 个正例帧里 **1200 帧**满足"该脚其余格全部 <0.7"（`pass8.py`；改用 0.5 阈值为 686 帧）——其中 **66 帧**同时是上表的轻载假接触，其余 1134 帧的脚载荷 ≥15% 参照（脚确有承重，属真实接触与阈值口径的混合，不在本次裁定范围内）。
- 下游导出面：`AnysoleWorkspace/tool/adapters/mmvp_series/fpp/export_v2t.py` 直接复制侧车的 `contact_smpl.gt`(2,96) 与 `pressure.pred/gt`(31,22)，`contact_gt_source="press2Cont_binary_vertex"` → 3 维顶点标签 + 8 个压力维原样进入 V2T 评估集。

### 4.5 附带发现：随附侧车的两个口径问题（与故障格无关，但同批登记）

1. **顶点 GT 用了 th=0.7（已退役默认值）**：实测"GT=0 但 sig>0.7" = **0 帧**，"GT=0 但 sig>0.5" = **4785 帧**；"GT=1 而 sig≤0.5" = 0 帧。→ 侧车 GT ≡ `sigmoid > 0.7`，与 `PED_tempKPCont.py:185` 的 0.5 不一致（全部侧车写于 09-27 22:58–22:59，早于 09-28 的裁定）。
2. **38 个 session 的 `pressure.gt` 用了旧权重**：用"实时权重"复算 sigmoidNorm 与侧车逐值比对，**101/139 完全一致（max|Δ|<1e-3）**，**38 个不一致**，全部集中在 **S8（9）、S12（11）、S13（18）** 三个受试者（其权重在 V3 双足承重修复中被改过）。

## ⑥ 值域 / 无 clip 登记建议

| 链路 | 现状 | 实测证据 | 建议登记 |
| --- | --- | --- | --- |
| 31×11 表示（`build_shared.py::build_mmvp`） | **无 clip、无过滤**，raw 直通 | 目标格逐值 == `right48[:,34]`（4204 帧抽样 0 处不一致）；全量最大 **10392.28** | 作为事实登记（非缺陷），但需注明"该列的值域上限是采集异常值，不是物理量程" |
| FPP-Net 原生 lib（live + backup） | **无 1023 假设** | `lib/` 全树 `1023` grep 命中 0；`maxNorm`（L117-118 live / L113 backup）**0 调用点** → 死代码 | 登记"FPP 与 1023 无关"，以免后续误改 1023 期望 |
| AnySole（`anysole/types.py:257` `PRESSURE_CLIP=1023.0`；`anysole/data/pressure.py:100-101,111`） | clip 到 1023 后 /1023 归一到 [0,1] | 归一化常数是**固定值**，不含受试者自适应 | 登记：同一条故障在 AnySole 链表现为"该维恒 1.0（满量程）"，**不产生权重膨胀**（无 per-subject 均值） |
| MotionPRO adapter（`AnysoleWorkspace/tool/adapters/MotionPRO/adapter.py:80,134-135,287`） | `PRESSURE_CLIP = 1023.0` → clip 后 /1023×255 成光栅 | 同上 | 登记：**两条链对同一故障的处理不同**（FPP 无界放大 × 会话自适应均值 vs AnySole/MotionPRO 截断饱和），这正是 FPP 侧出现 2.29× 权重漂移而 AnySole 侧不出现的原因 |

**值域差异本身不需要"修"**（它不是缺陷），但**需要登记**，理由：① 同一物理故障在三条链上的数值表现不同，跨模型对比时若不对口径会误判"某模型更差"；② FPP 的 `pixel_weight` 是 `Σ raw`（无上界），因此对异常值**线性敏感**，而 AnySole/MotionPRO 是 `/1023`（有界）——**这就是故障格只把 FPP 打死的原因**。
