## 开始清理前的条件

1. 01 的当前现场和投稿证据均有可验证恢复方式；主仓、独立 Baselines、HMR submodule、dirty/untracked/ignored 必要源码和外部数据均在恢复边界内。
2. 02/03 的采用表、公式、评分帧、有效分母、跨会话/折聚合、std、锚定及来源链已逐项核实。未解决差异明确列出；没有以删掉旧版本来冒充差异已解决。
3. 后续口径修订在独立工作分支或副本完成，保留投稿版本及新旧对照。修订范围若超出本任务授权，先列具体方案再询问；不要把已投稿论文自动替换成新的结果。
4. 04–06 给出精确候选、全仓读写方与逐一适配方案。公共依赖、初始化权重、原始逐折/逐会话指标与训练来源不能成为孤儿。

## 需要收敛的生成链

为每个最终实验记录现有命令、工作目录、环境、前置输入、输出、覆盖顺序和校验方法，至少区分：

- 数据与协议构建：raw/GT/offset/压力/虚拟 IMU → facts/表示/前端/adapter。
- 训练与选点：基座、FT、消融、基线、BiFoot/Yaw/先验；训练集/val/test 边界明确。
- 预测与固定预测重评：权重/配置 → 预测 → 钉定 session/frame manifest → 规范指标与有效分母。
- 聚合与展示：逐帧/会话/折原始结果 → 汇总 → 表图 → Q 项修正/替换步骤，避免运行旧生成器恢复旧口径。

指标公式优先继续使用现有公共实现；不要为“统一”再复制一份公式。整理配置/注册/显示入口时，按 04 的完整消费者清单适配，不另造用户未要求的执行框架或脚本。

README 如需后续修改，只写命令加一句简明说明；完整审计记录保留在本轮任务文件，不把 README 扩成长篇报告。

## 归档与待删除清单

按实验/资产建立逐项表：原路径、用途/版本、大小、证据、所有消费者及适配结果、归档目标、恢复命令、验收结果、是否请求用户确认。目录可展开到例外文件时，必须明确列出不能随父目录移走的内容。

优先顺序建议：

1. 已保存恢复点且无人运行依赖的历史笔记、旧 HMR/E3 叶子资产。
2. 已解除依赖的旧模型入口、配置、旧注册与无人消费的结果副本。
3. 已校验有独立备份的交付副本和旧探索结果。
4. 有完整输入/版本/环境/命令并验证恢复的昂贵缓存和优化中间产物。
5. Git 分支名与远端引用最后处理；独有提交先有可恢复 refs/bundle。不要自动删远端分支、force push 或改写历史。

本轮调研产物中的“候选”不构成删除批准。执行时先向用户展示完整路径清单并等待确认；按用户规则移动到 `/_trash/<日期>/`，保留原相对层次并避免覆盖。现有仓库内 `_trash/` 不能自动替代绝对路径。确认未到或目标不可写时，继续可独立完成的核验，不执行依赖该确认的移动。

## 最终验收

- 当前现场恢复：独立目录还原 refs、源码、dirty 状态与必要资产，并核对校验值。
- 投稿版本恢复：确认具体采用表图、原始指标、权重/预测/协议均能对应；没有论文输入则如实说明只能恢复磁盘实验版本。
- 管线恢复：分别记录数据可读、模型可载入、固定预测重评、原始结果再生成表图、完整推理/训练各层验证结果，不把未执行层写为通过。
- 口径一致：同一比较的每行使用相同定义和评分支持；所有跨表差异均有实际来源解释；不同任务统计口径显式标注。楼梯 p5 GroundPen 的适用限制保留。
- 移动后复查保留模型的 import/registry/CLI/配置读取、正式数据 URI、软链接和被采用图表生成链；运行与改动直接相关的既有验证，失败修代码，不删测试或绕过校验。
- 对拟移出路径再次全仓 `rg`，逐项解释剩余历史引用；只检查文件路径无命中不能代替动态注册、压缩包和外部链接核验。
- 记录实际移动清单、验证命令、退出码和原始输出；移动到同一磁盘回收区时不声称已释放磁盘空间。

最终汇报用 `complete` / `partial` / `blocked`。说明已经保存、已核验、已移动以及尚未完成的具体对象；保留可恢复版本和 rebuttal 所需命令入口。
