## 不能按 v3/v4 或模型名直接退役

- MotionPRO 当前投稿版使用 `adapter_v4_anysolebbox`、`carpet_v4_anysolebbox_<fold>`；Q5 保存 v4 task config，Q10 用该预测重评。它们不是失败实验。
- `Baselines/MotionPRO/lib/util/carpet_v2.py` 是 Q5 所列最终地毯实现；源码名 v2 不代表运行的是旧版配置。
- `adapter_v3_bvh24` 可能是旧 MotionPRO 输入，但其是否仍为 v4 生成前置需查代码、几何、软链接和 manifest。不能只看目录编号。
- Q15 仍引用 FPP-Net `adapter_v2_bvh24`、31×11 表示和 BVH24 元数据；Step2Motion 的姿态、位移和 BiFoot 初始化需分开确认。
- SAM3DB 可能不在最新 E2 主表，但仍可能为 Q3、历史对照或复核来源。模型未出现于一张表，不足以证明整支可删。
- `AnysoleWorkspace/tool/adapters/visual_baselines/generate.py` 使用 `work/visual_baselines` 参考树及 `visual_baselines_local`；当前该文件还有未提交修改，不能清掉被它读取的镜像或覆盖改动。

## 必做调查

1. 对每个模型建立真实版本表：源码仓库与 SHA、配置版本、输入表示、split、权重、预测、评测、最终采用表、补充 Q 项及所有读写方。记录失败/半成品的事实，不把“formal”目录名当作成功证明。
2. 展开 `Baselines/决策/`、`README`、`01_Baseline复现说明.md` 与实际 adapter/CLI 的差异，以现有原始结果和源码为证据。
3. 按目录拆分 `results/baselines/<model>/predictions/` 的 clean、occ、gap、scene、纹理、FT、local_gen 与 heldout/fold。检查 Q10 的新汇总及 side JSON，不能只保留旧 `test_comparison.json`。
4. 调查 Q3 的 `gvhmr_finetune`、`gvhmr_wham`、`work/q3_e5_ft`；区分最终 best checkpoint 和可再建中间状态。保留训练/验证选点、平移校准的使用数据和日志，交给 03 核对公平性。
5. 视觉交付包的 `PACKAGE_MANIFEST.json`、FILE_INDEX、history、reference_results、workspace 与恢复/传输清单一并核对。是否在别处有校验通过的完整副本必须拿出证据，不能用“应该已传输”判断可删除。
6. 比较副本按内容、配置、帧 ID 和语义身份判定。大数组可分阶段校验，最终拟删清单须可证明恢复；mtime、文件名、相同容量都不能单独判重。软链接/硬链接另计。
7. 把可移出版本、保留的最终版本、待修复管线、唯一资产和待确认外部副本分别列明；容量统计不重复计算父子路径。

## 验收

按模型提交精确去留表、读写方清单、保留的最小可复现链及恢复命令。至少为每个正式模型找到原始逐折/逐会话来源，并说明固定预测重评与从 RGB/压力重新推理两种恢复分别具备哪些资产。

附 Git 状态、版本查询、成员清单/校验、评分帧和原始指标对照的实际命令及输出。不要在调研阶段重训、重生成全部基线或修改任何指标；缺文件、数组长度/帧轴不一致时报告，不用截断或交集掩盖。
