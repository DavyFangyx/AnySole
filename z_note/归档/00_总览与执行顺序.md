## 所有 Agent 共用的约束

1. 先阅读本文件和自己的任务文件；调研结论追加到自己的任务文件，避免多个 Agent 同时改共享代码。原有实验计划和论文说明不在本轮直接改写。
2. 修改或移动任何现有路径前，以 `rg` 扫全仓库，包含隐藏文件、被忽略目录、独立基线仓库和临时目录。逐个登记读方、写方、导入、注册、URI、软链接和历史证据引用；引用类型须区分运行依赖与历史说明。大型 JSON、二进制、压缩包和仓库外目标另查，文本无命中不能证明无人使用。
3. 发现缺文件、长度、帧数、会话集合或指标覆盖不一致，报告原始事实；不补齐、截断、插值伪造或悄悄缩小集合。验证失败应定位并修复代码，不能放宽验收或忽略缺失项。
4. 调研不删除文件或 Git 引用。执行删除前，先列出精确路径和迁移目的地，等用户确认；禁止 `rm -rf`，按用户规则移动到 `/_trash/<日期>/`。仓库已有 `_trash/` 与这个绝对路径不同，执行前核实目标和权限，不能自行替代。
5. Git 标签不能保存未提交、未跟踪、被忽略文件、独立仓库、仓库外数据或环境；“已推送代码”不等于“实验可恢复”。不能只保留最终 CSV 和截图。
6. 每份结论使用 `complete` / `partial` / `blocked`，附验收命令、退出码和原始输出。`complete` 只表示该任务验收完成；不表示已批准删除。任务书与实际事实冲突时先停下询问。

每项拟归档对象至少写清：精确路径、用途/版本、容量、读写方、保留证据、替代来源、恢复方式、验收命令、尚未解决的问题。涉及指标再记录公式、评分帧、锚定和逐层聚合；这些是调研记录，不要求本轮新增程序字段或脚本。
