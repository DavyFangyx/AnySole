# 任务 01：统一指标求解器与模型真实输出能力

## 1. 任务目标

建立“模型真实输出能力 → 确定性派生量 → 公共指标求解器”的正式评测链路。

本任务统一同名指标的公式、单位、时间轴、有效帧和聚合方法，不要求各模型统一原生结果文件格式。执行时遵守以下原则：

1. 模型真实输出已经包含指标所需信息，但当前评测代码缺少求解器时，必须补充公共求解器，不能把指标标成不适用。
2. 模型确实没有指标所需输出时，结果写为原生格式支持的缺失值，展示端统一显示 `—`，不得填写 `0`。
3. GT 回填、模板替换、启发式推导、仅用于可视化的占位字段和不唯一的逆解，不能用于获得指标资格。
4. 删除 common19。SMPL 模型使用原生 SMPL 骨架及 SMPL GT；Step2Motion 使用原生 BVH-23 及 BVH GT。
5. Step2Motion no-IMU 只是实验探针，不注册成独立模型，不进入正式模型排名。
6. pressure_toolkit 的 shape 和 mesh 来自模板与拟合过程，因此不报告公共 `pve_mm` 以及任何 shape/vertex 类指标。

## 3. 模型能力声明

在正式模型注册信息中声明真实输出能力。能力描述模型或方法真正产生的输出，不能根据导出文件中“存在某个数组”自动推断。

建议字段如下：

```yaml
capabilities:
  joint_positions: true
  direct_joint_rotations: false
  root_translation: true
  root_rotation: true
  predicted_surface: false
  predicted_shape: false
  pressure_prediction: false
  contact_prediction: false
```

同时记录关键输出的来源，至少区分：

- `model_prediction`
- `method_optimization`
- `ground_truth_fallback`
- `template_reconstruction`
- `derived_for_visualization`

评测器只接受指标许可的来源。GT fallback、模板重建和可视化占位字段不能使模型获得相应指标资格。能力声明与实际产物不一致时必须明确报错，不能静默使用替代数据。

### 3.1 正式能力矩阵

| 模型或方法 | 可用于公共评测的真实输出 | 应计算的指标 | 明确不适用 |
|---|---|---|---|
| AnySole motion | SMPL pose、root translation、root rotation | MPJPE、PA-MPJPE、W-MPJPE、MPJAE、root、orientation、temporal、关节版 foot sliding；PVE 按现有批准的 SMPL 协议处理 | 正式 contact |
| MotionPRO | SMPL pose、shape、translation、rotation | 相应 SMPL pose、surface、rotation、trajectory、temporal 指标 | 正式 contact |
| pressure_toolkit | 优化得到的 pose、translation、root rotation、joint positions | joint、rotation、trajectory、temporal、关节版 foot sliding | `pve_mm`、所有 shape/vertex 类指标、正式 contact |
| VP-MoCap / PoseTransOpt | 实际落盘的 pose、beta、translation | 由真实输出充分支持的指标；缺 solver 时补 solver | 正式 contact；缺少必要输出的指标 |
| Step2Motion 主干 | BVH-23 joint positions、预测 root translation、BVH root rotation | MPJPE、PA-MPJPE、W-MPJPE、root ATE、root orientation、temporal、关节版 foot sliding | MPJAE、PVE、shape/vertex、正式 contact |
| V2T 模型 | 显式 pressure prediction | 确认的 V2T 九项 | motion；正式 V2T 表中的 contact |

实现者必须先由适配器读取实际产物并核对能力矩阵。模型原生 evaluator 没有某项指标，不构成不适用；只要真实输出充分，就必须补充求解器。

## 4. 具体改动

### 4.1 删除 common19

从 `compare_core.py` 删除以下正式协议内容：

- `COMMON_JOINTS`
- `SMPL_COMMON_NAMES`
- `BVH_COMMON_NAMES`
- `COMMON_EDGES`
- `select_common_joints()`
- `select_common_rotations()`
- `common_edges_for()`
- common19 专用元数据、日志和描述

向任务 03 提供以下接口保证：

- SMPL 预测以原生 SMPL 关节顺序对 SMPL GT 计算。
- Step2Motion 以原生 BVH-23 顺序对 BVH GT 计算。
- 不再把两种表示裁剪成相同关节数量。
- 返回可供消费端记录的 `smpl24-native` / `bvh23-native` 协议标识。
- 提供原生骨架边查询接口，展示布局和 GT 面板由任务 03 实现。

不得保留“common19 用于数值、原生骨架用于展示”的双轨正式协议。

### 4.2 按必要输入分派指标

| 指标 | 必要输入 |
|---|---|
| `mpjpe_mm`、`pa_mpjpe_mm` | 预测与 GT joint positions |
| `w_mpjpe100_mm` | 世界系 joint positions 和真实预测的 root translation |
| `root_ate_mm` | 真实预测的 root translation |
| `root_orientation_deg`、`root_orientation_drift_deg` | 模型或方法输出的 root rotation |
| `mpjae_deg` | 模型直接输出且语义可信的 joint rotations |
| temporal 指标 | 预测 joint trajectory、GT、真实时间戳 |
| `foot_sliding_mm` | 预测足部 joint trajectory、对应 GT、时间戳 |
| `pve_mm` | 获准进入公共表的真实 surface/SMPL 输出 |
| `contact_f1` | 经过训练并显式导出的 contact prediction |
| V2T 九项 | 显式 pressure prediction |

求解器应声明必要输入及允许的数据来源。输入充分但求解器缺失时必须实现求解器；只有必要输入缺失或来源不合法时才输出 `—`。

### 4.3 Root orientation

把 `anysole/utils/eval_protocol.py` 中现有 yaw 公式迁入公共指标模块，作为唯一实现，并完成字段改名：

- `yaw_abs_deg` → `root_orientation_deg`
- `yaw_drift_deg` → `root_orientation_drift_deg`

定义不变：

- 只评估 yaw。
- absolute 为预测 yaw 与 GT yaw 的周期角差。
- drift 为预测和 GT 各自相对首帧 yaw 变化的周期角差。
- 正确处理 `±180°` 环绕。

Step2Motion 使用解析后的 BVH Hips/root rotation调用相同求解器，不另写公式。

### 4.4 Contact

以下数据不能进入正式 `contact_f1`：

- AnySole 的 `soft_contact_from_keypoints()` 结果；
- 从脚部高度或速度阈值反推的预测接触；
- GT contact 或作为模型输入的 contact；
- 未被正式定义为模型预测接口的 archive contact 字段。

当前 motion 模型的正式 `contact_f1` 均为缺失，展示为 `—`。训练监控、接触正则和历史诊断可以保留，但必须标为 diagnostic，不能进入正式跨模型表或 brief 候选指标。

### 4.5 V2T

V2T 正式指标固定为九项：

- `T_corr`
- `T_mae`
- `T_rmse`
- `pressure_force_mae`
- `pressure_force_rmse`
- `pressure_force_r2`
- `pressure_cop_error_left`
- `pressure_cop_error_right`
- `pressure_cop_error_mean`

从 `MODE_METRICS["V2T"]`、R_Test4 fieldnames、逐 session 输出、aggregate、AnySole brief 和其他 V2T 展示中移除 contact 指标。原始 archive 中的历史字段无需删除，只停止作为正式 V2T 指标消费。

### 4.6 PVE、shape 与 vertex 指标

统一裁定：

- `pve_t_mm` 从公共定义删除。
- `shape_vertex_std_mm` 仅可作为适用模型的内部诊断，不进入公共比较指标。
- Step2Motion 不报告 PVE 或 shape/vertex 指标。
- pressure_toolkit 不报告公共 `pve_mm` 或任何 shape/vertex 类指标。

pressure_toolkit 的逐帧 `shape`、`model_scale_opt` 以及通过 `SMPL_MMVP` 模板生成的 vertices 可以保留在原生预测或可视化导出中，但必须标注：

```text
surface_source=template_reconstruction
shape_source=method_fitting
public_surface_metrics=false
```

评测端即使读到 `vertices_world` 也不得自动计算 PVE。禁止使用 GT beta 重建 pressure_toolkit 网格来获得公共 PVE，因为这评估的是人为替换后的表面，而不是该方法的真实 shape/mesh 输出。

其他 SMPL 模型是否报告 PVE，依据其已批准协议和真实输出能力分别判定，不能从 pressure_toolkit 的裁定外推。

### 4.7 Foot sliding

公共 `foot_sliding_mm` 改为关节版，避免依赖 SMPL 顶点和 shape/template：

- SMPL 使用左右 ankle/foot 语义关节。
- BVH 使用 `LeftFoot`、`RightFoot`、`LeftToeBase`、`RightToeBase`。
- 所有模型使用相同的 GT 接触判定、时间轴、单位和聚合公式。
- 原顶点版可以保留为 SMPL 专属诊断，但必须使用不同字段名，不能与公共关节版同名。

### 4.8 Step2Motion 主干与 no-IMU 探针

正式 Step2Motion 必须验证：

- 配置输入为 50 维；
- 使用原版包含的 IMU 条件；
- `model_trans.pth` 存在并实际参与推理；
- 轨迹指标来自 translation head 的预测。

no-IMU 的处理规则：

- 只作为实验探针，不加入正式模型 registry；
- 不作为 R_Test2 独立模型或排名行；
- GT translation fallback 不参与任何轨迹或世界系指标；
- 可以保留独立实验报告，用于观察移除近似 IMU 后的姿态变化；
- 不删除已有 checkpoint、数据或预测产物。

原版 `Baselines_Backup/Step2Motion` 已包含 50 维输入和 translation model。当前主干必须保留这些能力；后加的 `--no-imu` 与关闭 translation head 只能服务探针，不能反向改变正式主干。

## 5. 验收标准

### 5.1 静态检查

- 正式评测代码中不再存在 common19 的常量、选择函数、协议元数据或调用。
- `MODE_METRICS["V2T"]` 只含九项压力指标。
- pressure_toolkit 的能力声明明确禁止公共 surface/shape/vertex 指标。
- no-IMU 不在正式模型 registry 中。
- 每项正式指标可以追溯到必要输入、输入来源和唯一求解器。

### 5.2 数值测试

1. 预测等于 GT：SMPL 原生关节和 BVH-23 原生关节的适用指标均为零，且不经过 common19。
2. Root orientation：相同旋转时两项为零；固定 yaw 偏置只影响 absolute；已知线性漂移得到预期 drift；跨越 `±180°` 时不跳变。
3. 缺失能力：Step2Motion 的 MPJAE、PVE、shape/vertex、contact 为缺失；pressure_toolkit 的 PVE、shape/vertex、contact 为缺失，即使 archive 中存在模板 vertices 和 fitted shape。
4. GT fallback：没有真实 translation 输出时，不产生 root ATE、W-MPJPE 或其他世界轨迹指标。
5. V2T：逐 session、汇总、CSV/JSON 和展示严格为九项；R_Test2 与 R_Test4 对同一预测的数值一致。
6. Step2Motion：正式主干实际加载 `model_trans.pth`，轨迹指标随预测 translation 改变；no-IMU 不进入正式比较表。
7. 能力守卫：移除某项必要输出后，对应指标明确缺失或评测失败，不能静默使用 GT、模板或启发式数据补齐。

## 7. 禁止事项

- 不把各模型原生结果格式统一成同一种 JSON 或 NPZ。
- 不删除或移动 checkpoint、原生预测或 pressure_toolkit 大体量结果。
- 不将 Step2Motion no-IMU 注册为正式模型。
- 不保留 common19 作为正式数值协议。
- 不用 GT translation、模板网格或可视化占位字段补齐模型能力。已批准的 SMPL
  pose-only PVE 可以按其正式协议使用 GT beta；该例外不得用于 pressure_toolkit，
  也不得让本来不输出 SMPL pose 的模型获得 PVE 资格。
- 不从 joint positions 逆解完整局部旋转后计算 Step2Motion MPJAE。
- 不从运动学阈值生成正式 contact prediction。
- 不给 pressure_toolkit 计算公共 PVE 或 shape/vertex 类指标。
- 不把缺失值写成 `0`。
- 不在本任务中清理旧结果，只提交精确清理清单给结果清理任务执行。
