## 1. MotionPRO（3 高危 + 2 中危）

### M1【高】foot 接触损失把接触权重施加在错误关节上
- `app/train_frappe.py:31,48-53`：接触列 `contact[:, [6,7]]` 取左/右脚（正确），但同一索引被用在关节轴上：`pred['joint'][:, self.footContactIds]`。SMPL-24 序实测：关节 6=Spine2、7=L_Ankle，足是 10/11。
- eval 侧（`train_frappe.py:69,137-140`）用 `FOOT_JOINT_IDS=[10,11]`；文档（z_note/模型完整结构.md:486）记载意图是监督关节 10/11。**训练与自身 eval 口径矛盾**。
- 后果：foot 损失（权重 5）在接触帧上监督的是 Spine2 与左踝的绝对坐标，脚从未获得接触加权监督。

### M2【高】contact 阈值 100 使左脚接触列恒为 1
- `data_prep/prepare_sequences.py:37,178-184`：整脚 48 格原始 ADC 和 > 100 判接触。实测左脚逐帧和最小值 148（摆动期 150~500）——左脚任何帧都超阈值；144 序列中 130 个左脚接触率 ≥0.99。
- 后果：(a) 训练 foot loss 左列权重恒 1；(b) eval `gt_contact = (contact[:,[6,7]]>0.5).any(dim=1)` 恒 True，**contact IoU 退化为"预测接触率"——恒预测接触的模型 IoU=1.0**。与 f6_soft 同构：阈值把两态信号压成常量。

### M3【高】压力时间轴与动捕系统性时移（中位 -11 帧 / 275ms）
- `prepare_sequences.py:373-380`：压力按视觉时钟插值、BVH 按 t_grid-offset 采样。实测 96 个 session 接触↔足高互相关：中位 -11 帧，88% |时移|≥8 帧（200ms）；逐帧证据 S12072 接触在脚到最低点后才置 1，接触与足高半周期反相。视频↔动捕对齐良好（bbox 互相关 ~0），是**压力支路**错位。
- 后果：V+T→M 训练配对在多数 session 错位约 250ms。归因疑似：PressureWasher fake_marked 时间轴或 AlignReviews 偏移 vs prepare_sequences 按时间插值。

### M4【中】make_splits.py 覆盖统一 split
- `data_prep/make_splits.py`：默认按 (subject,action) 分组→**同 subject 跨 train/test**、val==test；`prepare_sequences.py:279-283` 文案引导运行。违反统一协议第 9 条（split 唯一来源、subject-disjoint 92/12/36）。当前磁盘未触发，属隐患。

### M5【中】零填充帧以零 GT 参与全部四项损失
- `lib/dataset/image_pressure.py:218-228` 填充帧 GT=0、valid=0；`app/train_frappe.py:43-66` 损失从不消费 `item['valid']`。实测 144 序列 54000 帧中 1320 帧（2.4%）为填充帧，模型被明确训练成"零输入→零姿态"。

## 2. Step2Motion（1 高危 + 1 中危 + 1 低危）

### S1【高】gait.pt 切分过期且 val==test（选择泄漏）——违反统一 split 协议
- **协议定性**：《统一数据协议》第 9 条与 AnysoleWorkspace/README.md 1.1 从项目一开始就规定：`splits/default/splits.csv` 是**全体模型唯一来源**、"split 只生成一次，任何模型不得自行重新划分"、"主模型与各基线共同使用同一个 split"。S1 不是"数据过期"一个时间问题，而是**协议违反**：Step2Motion 在 gait.pt 转换时自行切分（66/34/34 且 val==test），未读取 canonical splits.csv。同审计已核验 MotionPRO（image_pressure.py:79-92）与 AnySole 均正确消费统一 split，Step2Motion 是唯一越轨者。
- 落盘切分 66/34/34，统一协议 92/12/36；**val 与 test 的 34 个 session 完全相同**（两个 .pt 的 insole 均值逐通道一致）；与 canonical test 仅 13/36 重叠，canonical train 的 59 个 session 在 gait.pt 中缺席。
- 时间线：gait.pt 构建 09-12，splits.csv 定稿 09-20——数据早于定稿且从未重建。
- 后果：早停用 val，test 指标全在模型选择集上；与其他基线的 test 集不可比，跨基线对比语义失效。修复：用 canonical splits.csv `--force` 重建两套 .pt + normalizer + 重训。

### S2【中】评估关节索引沿用上游骨架
- `src/metrics.py:320-352` 的 end_effectors/toes/legs 索引按上游骨架硬编码，gait 数据集用 CMU-23 序。实测映射："MPJPE Legs"实际测的是 {Spine,Spine1,Spine2,Spine3,Neck,Head,LeftShoulder,LeftArm}；"MPEEPE toes"测 {Spine3,LeftArm}。报告里的"腿部误差"数字语义错位（MPJPE 全体与 MRPE 不受影响）。

### S3【低】压力未按协议归一化
- `process_gait.py:150-199` 直接池化原始 ADC。实测跨日期 CSV 峰值 857~1966（2.3 倍增益差），force 通道物理含义随 session 硬件增益漂移；与主模型 [0,1] 口径也不同。

## 3. VP-MoCap（2 高危 + 3 中危 + 2 低危；F0 另报告）

### V1【高】PoseTransOpt 帧对齐断裂：fake 帧缺口导致三序列错位或崩溃
- FPP 只输出不含 fake 帧的 5 帧窗口（`PED_tempKPCont.py:137-155` + `build_fpp_metadata.py:162-170`），而 keypoints（`run_rtmpose_halpe26.py`）与 CLIFF pose 覆盖全部 n 帧；`dataset_mmvp.py:189-218` 裁 `[2:-2]` 后按**位置**拼装，帧语义从第一个缺口起漂移。
- 实测 S6011（n=398，fake 4 段）：contact 331 文件 vs keypoints 394 帧，328/331 对帧号不一致，首个错位在 index 3；全量运行在 frame=331 IndexError 崩溃；`--max-frames` 冒烟则**静默错帧**。19/140 session 受影响（train 11/val 2/test 6，含 test 的 S14011/S14013/S14022/S14062/S14063/S14091）。`run_full_mmvp.py` 守卫拦不住。

### V2【高】CLIFF_results.npz 契约违反：多人检测行混入
- 140 份 npz 全部生成于 09-22（早于生成器守卫）；bbox 源含每帧多人框 → pose 行数=人检测数。实测 S6011：pose 1290 行 vs 帧数 398（每帧 3.24 人）；**133/140 份 pose 行数≠帧数**。
- 后果：(a) 全量运行崩溃 / 冒烟把"行人 A 的 crop 姿态"与"患者帧 B"拼对；(b) `np.mean(pred_betas)` 把旁观者体型平均进患者 betas，transolver 骨长被污染；(c) savgol 平滑跨人滑动。生成器已带守卫但 `if not output.is_file()` **跳过已存在的坏文件，不会自动重生成**。

### V3【中】pixel_weight 口径错配，压力 GT 饱和
- `build_fpp_metadata.py:125-135,196-200` 用站立帧 4×12 裁剪区和（96 格）当体重，`InsoleModule.sigmoidNorm` 却除以 484 掩膜格数——参考偏小 3-4 倍。实测 S5011：参考 6.76/格 vs 真实均载 21.1/格；>0.9 的格占 33.4%（全网格参考下 18.6%）——载重格动态范围被压向 1.0，细粒度压力渐变被压缩。影响全部 140 session 的压力 GT。

### V4【中】flip 增强不对称（继承上游，但已启用）
- `PED_tempKPCont.py:158-164`：flip 时 kp x 取负**不交换左右关节索引**，insole/contact 却换脚。训练配置 `is_aug=True`（yaml 未关闭，50% 概率 flip）——约半数样本教"左踝站立相↔左槽高压"与"左踝站立相↔左槽低压"互相矛盾，左右脚压力特异性被抹平（对步态不对称评估语义有害）。与上游逐行一致，属继承缺陷被激活。

### V5【中】f6_soft 数据被并发会话二值化重生成（{0,1}）
- 详见 `FPP-Net接触GT语义错配_问题报告_20260927.md` §8：16:13 contact_labels.py 被外部会话改为导出二值化，144 份全部重生成；33/144 session 两脚全 1（S5011 等连续 512–635 帧无 0）。§0/§1 的 4 档软值计数过期。

### V6【低】相机主点弃真实标定
- `configs/task/MMVP.yaml` + `depth_utils.py:31-39` 用图像中心 (812,620)；`calibration.npy` 有真实 K 未用。实测主点偏差 dcx 18.5–40.4px、dcy 22.4–71.9px——3m 处点位偏置 (5.4cm, 15.5cm)。

### V7【低】loss_2d 置信度索引顺序错配（继承上游）
- `lib/loss/losses.py:19-25`：位置经 HALPE→OpenPose 映射，置信度未重排即用 OpenPose 分组索引——"右肩"误差被"右眼"置信度加权，"左跟"置信度永不被使用。

## 4. pressure_toolkit（2 高危 + 2 中危 + 3 低危）

### P1【高】地面锚定与真实行走面错位 ~1.45m
- `AnysoleWorkspace/tool/prepare_mmvp_observations.py:98-130` 把标定棋盘格平面当行走地面（floor y=0）。实测四日期真实行走面在 floor 系 y≈1.305/1.350/1.449m；拟合结果脚踝 y=0.03~0.14（被 penetrate 权重 15 钉在 y=0）、骨盆 y=1.15~1.31——**脚底在真实地面下方 1.3~1.4m**。
- 后果：深度项（权重 60）把身体往真实地面拉、穿透/接触把脚钉在 y=0，两项矛盾 1.45m；输出坐标系语义错误（任何假设"y=0 是地面"的下游都错）。上游用 `calculateFloorNormal` 从深度估计地面（该函数仍在库中）。

### P2【高】深度 mask 换成语义不同的人体前景→0.4–5m 范围掩码
- `prepare_mmvp_observations.py:137-146` 按深度范围选点，掩码覆盖全帧 54.8%。实测观测云组成：**地面 79.4%、背景 13.3%、人体仅 7.3%**。`depthTerm.findCorrs` 对每个观测点取 k=32 最近 SMPL 顶点、`np.argmax` 无有效性过滤（上游原样）——上游云是人体（Chamfer 语义），现在深度损失（权重 60）被地面几何主导，人体表面拟合信号被淹没。
- 与 P1 叠加：地面点把身体拖向真实地面，与 y=0 的接触锚定对抗。

### P3【中】深度云默认降采样一半
- `fit_single_frame.py:51-56` + config 默认 `--depth-sample-stride 2`：观测点 1.1M→0.55M，kNN 查询集与损失数值改变；注释"without changing the fitting math"只对渲染画布成立，对观测云不成立。与上游结果不可比。

### P4【中】拟合消费"仅展示端"触觉产物 + 假帧压力当真实观测

## 6. 共性根因（这些 bug 不是孤立的）

1. **阈值/广播把信号压成常量**（F0、M2、V5 全 1）：接触判据设计时没算过实际数据的边际分布，常量列静默毁掉损失/指标语义——这类 bug 不报错、指标还"正常"。
2. **协议切换后旧索引/旧口径残留**（M1、S2、V7、P8）：关节序换 SMPL-24/CMU-23 后，损失/指标的硬编码索引没跟着换；继承的上游索引缺陷在换数据格式后被激活。
3. **fake 帧/时间轴没有贯穿全链**（V1、M3、P4、M5）：fake 帧在 A 环节剔除、B 环节保留，按位置拼装就错位；压力时间轴与视觉时钟的换算只在个别环节做对。
4. **多环节各自"就地适配"而非协议级对齐**（P1、P2、V3、V6、P3）：地面、掩码、参考值、主点、降采样各改一处，互不知晓，凑出来的观测在语义上互相矛盾。
5. **"仅展示/不参与训练"的产物被当训练输入**（P4）：协议声明与实际消费脱节。

## 9. 补充裁定（2026-09-27 用户追加）

### 9.1 接触 GT 统一尚未完成：f6_soft 暂作 GT，AnySole/MotionPRO 未同步（滞后）

现状口径（用户明确）：f6_soft **暂时作为接触 GT 数据**（经 16:13 二值化重生成后实际为
motion_f6 硬标签 {0,1}）。但接触 GT 在全模型的落地并不同步：

- FPP-Net：已切 f6_soft（本次审计对象）；
- AnySole：`--contact-method` 默认 **tactile_abs**（原 contact.npy）；
- MotionPRO：`contact_method` 配置默认 **tactile_abs**（image_pressure.py:78）。

即同一项目内三个模型此刻使用**两种不同的接触 GT 语义**（f6_soft 硬标签 vs tactile_abs 压力阈值），
跨模型接触指标/接触监督不可比。这是 GT 切换的**滞后**：定稿一个口径后应全模型统一落地，
否则"f6_soft 定为接触 GT"的裁定只在 FPP-Net 一条链上生效。方案 A（FPP-Net 回退 press2Cont）
执行时，此项需一并裁定：三模型接触 GT 的最终统一口径是什么、切换顺序如何。

### 9.2 split 协议自始规定全体共用（补强 S1）

S1 的定性见 §2 修订：统一 split 是项目初始协议（统一数据协议第 9 条、README 1.1），
"主模型与各基线共同使用一个 split、只生成一次、任何模型不得自行重新划分"。
Step2Motion 自行切分是协议违反，不是可接受的历史差异。

### 9.3 时间对齐与 fake 清洗应在 workspace 层统一完成，模型内部不应处理文件级对齐（工程实现不足）

M3（MotionPRO 压力↔动捕 -11 帧时移）与 V1（PoseTransOpt fake 帧缺口错位）的根因相同：
**基线复现各自在自己的数据准备代码里重做（或漏做）文件级对齐与清洗**，而 AnySole 主链
已存在对应的 canonical 管线：

- `anysole/data/pressure.py::load_session_pressure`：按 `t_grid = visual_start_s + n/40`
  统一压力时间轴；
- `AnysoleWorkspace/tool/contact_labels.py::load_aligned`：BVH 重采样、offset 换算、
  与压力在 40Hz 网格对齐——审计实测该管线与 contact_bvh_h 一致率 99.5%。

基线没有走这条管线：MotionPRO `prepare_sequences.py:373-380` 自行按 t_us 插值压力
（导致 M3 系统性时移）；FPP 侧 `build_fpp_metadata.py` 自行剔除 fake 帧窗口而
keypoints/CLIFF 不剔（导致 V1 按位置拼装错位）。**正确分层**：

1. workspace 层统一产出对齐/清洗后的数据（时间轴对齐、fake 帧标记、帧号主键、
   接触/压力/关键点/姿态各模态已 join 成同帧网格）；
2. 模型/基线层只消费成品数据，不做文件级对齐、不做帧选择——模型内部"处理文件"即越界；
3. 这与 workspace 重组议题（derived/ 按 shared/models/display 分层，shared 由工具层
   唯一写入）是同一工程原则的两个面。

由此 M3、V1 的修复应落在 workspace 工具层（统一对齐产出），而不是在各基线数据集代码里打补丁。
