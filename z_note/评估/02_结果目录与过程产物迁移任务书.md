# 任务 02：结果目录与过程产物迁移

## 1. 任务目标

本任务只处理结果目录职责、生产/消费路径和历史过程产物迁移，不修改指标公式，也不要求各模型使用相同的预测文件格式。

三个根目录的职责必须固定：

- `Baselines/`：模型与方法的源码、原始配置、运行入口。不得继续写入正式运行结果。
- `AnysoleWorkspace/`：数据输入、适配数据、初始化结果、优化过程文件、缓存和其他可重建中间产物。
- `results/`：checkpoint、最终预测和最终评测结果。展示端只从这里消费正式结果。

所有正式基线在 `results/baselines/<baseline>/` 下至少提供：

```text
predictions/    # 最终可评测预测，必需
metrics/        # 对 GT 的最终评测结果，必需
```

训练型模型可以另外提供 `checkpoints/`、`logs/` 和 `tensorboard/`。优化方法没有 checkpoint 时不得创建空的 `checkpoints/` 目录。

## 2. 已核验的现状

### 2.1 pressure_toolkit

`results/baselines/pressure_toolkit/` 当前约 61 GB，却主要保存优化过程文件：

- `gt_depths/`：约 60 GB；
- `meshes/`：约 1.4 GB；
- `results/`：逐帧 `smpl_*.npz`，约 13 MB；
- `yamls/`、`temp/`、`logs/`；
- 顶层大量 `Sxxxx/<date>/<subject>/<session>/`，其中是 CLIFF 初始化 NPZ 副本。

这些文件是初始化、逐帧拟合、调试或可视化过程产物，不是供 `results_display` 直接消费的最终结果。

当前写入链为：

1. `AnysoleWorkspace/tool/run_cliff_mmvp.py` 生成 CLIFF 初始化，并同时复制到 VP-MoCap workspace 和 `results/baselines/pressure_toolkit/Sxxxx/...`。
2. `Baselines/pressure_tookit/run_full_mmvp.py` 默认将 `--output-dir` 设为 `results://baselines/pressure_toolkit`。
3. `Baselines/pressure_tookit/main_singleview.py` 在该根目录中创建 `results/`、`meshes/`、`yamls/`、`temp/` 和 `gt_depths/`。
4. `AnysoleWorkspace/tool/export_baseline_motion.py` 再从逐帧拟合结果组装 session 级预测。

路径还存在三类错误：

- 源码、workspace、dependency 和结果路径同时使用 `pressure_tookit` 与 `pressure_toolkit`；
- pressure_toolkit exporter 将最终预测写入拼错的 `results/baselines/pressure_tookit/`；
- `validate_baseline_exports.py` 缺少 `baselines/` 层级，实际检查的是 `results/MotionPRO`、`results/pressure_tookit` 和 `results/VP-MoCap`。

### 2.2 FPP-Net 与 VP-MoCap

当前 FPP-Net 的 V2T 压力输出和 PoseTransOpt 的 V2M 运动输出混用 `VP-MoCap/predictions/eval_motion/`，且 FPP-Net exporter 还会写入缺少 `baselines/` 层级的 `results/VP-MoCap/`。

必须按实际输出组件拆分：

- FPP-Net 负责 V2T 压力预测；
- PoseTransOpt 消费 FPP-Net 等上游结果并产生 V2M 的 SMPL pose、shape 和 translation；
- 展示名称使用 `VP-MoCap (FPP-Net + PoseTransOpt)`，不得把最终运动结果标成 FPP-Net 单模型结果。

## 4. 实施任务

### 4.1 修改生产端

1. 修改 `run_cliff_mmvp.py`：
   - canonical CLIFF 初始化写入 `AnysoleWorkspace/derived/pressure_toolkit/initialization/`；
   - PoseTransOpt 所需的 `CLIFF_results.npz` 继续进入对应 session workspace，可采用复制或稳定链接；
   - 停止向 `results/baselines/pressure_toolkit/Sxxxx/...` 写入初始化副本；
   - smoke 输出继续隔离，禁止复制到 canonical 路径。

2. 修改 pressure_toolkit launcher：
   - `run_full_mmvp.py` 的默认输出根改为 `workspace://derived/pressure_toolkit/fitting`；
   - `init_data_dir` 必须显式指向新 initialization/fitting 根；
   - single-flight lock 和运行日志放在 fitting 根；
   - resume、已有 shape 和最后一帧判断全部使用新根。

3. `main_singleview.py` 可以保留原生的五类子目录结构，但其输出根必须来自 workspace，不能回落到 `results/`。

### 4.2 修改最终导出与评测出口

1. `export_baseline_motion.py`：
   - pressure 输入默认读取 `AnysoleWorkspace/derived/pressure_toolkit/fitting/results/`；
   - pressure 最终预测写入 `results/baselines/pressure_toolkit/predictions/eval_motion/<session>.npz`；
   - PoseTransOpt V2M 写入 `results/baselines/VP-MoCap/predictions/eval_motion/<session>.npz`；
   - FPP-Net V2T 写入 `results/baselines/FPP-Net/predictions/v2t/<session>.npz`；
   - 每份最终预测保留 session、frame index、valid mask、单位、坐标系和 `source_native_output`，以便追溯到 workspace 原生产物。

2. 各方法的最终评测写入对应 `metrics/`。格式可以维持各方法现状，但必须同时包含 test split 的逐 session 结果、汇总结果和协议元数据。

3. pressure_toolkit 不报告公共 `pve_mm`、`shape_vertex_std_mm` 或其他 shape/vertex 类指标。该方法使用 SMPL/SMIL template 和拟合 shape，这类数值不能作为与直接预测 SMPL 网格模型同口径的公共指标；输出使用原生缺失值，展示统一为 `—`。不得通过替换为 GT beta、固定 beta 或重建另一套顶点来补齐这些指标。

4. pressure_toolkit 仍可评估由其真实优化输出充分支持的关节、root translation、root orientation 和时序指标。缺少原生 evaluator 不是取消指标的理由，应由统一求解器补齐。

### 4.3 修改消费端和校验器

1. `validate_baseline_exports.py` 的模型根全部改为 `results/baselines/...`，并分别校验 motion archive 与 V2T archive，不能用一个固定 SMPL schema 校验所有任务。
2. `models_modes.yaml`：
   - pressure_toolkit 指向正确拼写的 prediction 根；
   - V2M 指向 VP-MoCap；
   - V2T 指向 FPP-Net；
   - 不再从错误的 `results/VP-MoCap/` 或 `results/baselines/pressure_tookit/` 读取。
3. 同步修改 readiness、数据准备、queue、运行脚本和 `results_display` 中的路径引用。必须逐项审核 `rg "pressure_tookit"` 的命中，禁止不加判断地全局字符串替换。

### 4.4 统一拼写

运行数据与结果的 canonical 名称固定为 `pressure_toolkit`，用于 workspace、dependency
URI、结果目录、配置键和展示注册。源码仓库目录保留其历史名称
`Baselines/pressure_tookit/`，与用户确定的“仓库 tookit、结果区 toolkit”一致。

实施时分别处理：

- `Baselines/pressure_tookit/` 源码目录保持不变，仅修正其内部写出的 runtime/result 路径；
- `AnysoleWorkspace/derived/pressure_tookit/`；
- `AnysoleWorkspace/dependencies/pressure_tookit/`；
- Python `sys.path`、配置 URI、shell/queue 命令、README 和结果路径。

禁止在本任务中物理改名源码目录。所有调用源码的 `sys.path` 和命令继续指向
`Baselines/pressure_tookit/`；只有 workspace 与 results 的新写入路径使用
`pressure_toolkit`。不得让两种拼写继续同时产生新的 runtime/result 数据。

## 5. 61 GB 过程树迁移安全要求

执行 agent **不得自行删除** 当前 `results/baselines/pressure_toolkit/` 的 61 GB 旧树。本任务中的删除只能形成候选清单，必须由用户和主 agent 查验并明确授权后执行。

迁移分四阶段：

### 阶段 A：只读盘点

生成迁移 manifest，至少记录：

- 源相对路径、文件类型、字节数、mtime；
- 按 date/subject/session 汇总的文件数和总大小；
- `smpl_*.npz` 的帧号连续性、首末帧和缺帧；
- CLIFF 初始化、init shape、session 拟合、mesh、GT depth、YAML、temp 和 log 的归属；
- test split 的 session 覆盖率。

manifest 放在迁移工作记录中，不能写入将被迁移的源目录。

### 阶段 B：复制并核验

- 优先按 date 分批复制到新 workspace；不得直接移动后删除源。
- 每批核对文件数、总字节和抽样 SHA-256；关键 NPZ 必须可打开并检查字段。
- 跨文件系统时不得把 `mv` 当作原子操作。
- 若磁盘不足以容纳双份数据，停止迁移并提交分批释放方案，不能自行删源腾空间。

### 阶段 C：切换 pipeline

- 用新路径完成一个 test session 的 resume/dry-run；
- 从新 workspace 导出 session 级 prediction；
- 运行 validator、metrics 和 display 的只读消费检查；
- 再对完整 test split 验证覆盖率。

### 阶段 D：提交删除候选，不执行删除

候选包括：

- 旧 `gt_depths/`、`meshes/`、`results/`、`yamls/`、`temp/`、`logs/`；
- 顶层 `Sxxxx/` CLIFF 初始化副本；
- 拼错的 `results/baselines/pressure_tookit/`；
- 错误层级的 `results/VP-MoCap/`。

清单必须标明每个候选的新位置、核验结果、是否有独有文件以及可恢复方式。未经单独授权，不删除任何候选。

## 6. 禁止事项

- 禁止删除或覆盖 checkpoint、最终 prediction、最终 metrics 和唯一的原生拟合结果。
- 禁止为统一目录而统一各模型的预测文件格式。
- 禁止把 GT、模型输入、模板值或启发式结果写成模型预测输出。
- 禁止为 pressure_toolkit 计算公共 PVE/shape 指标。
- 禁止让 `results_display` 扫描 workspace 过程目录、backup 或 experiments。
- 禁止在未完成新路径全链路验证前清理旧路径。

## 7. 交付物

执行 agent 需要提交：

1. 修改文件列表和每个生产/消费入口的新旧路径对照；
2. 迁移 manifest 及按 date/session 的核验报告；
3. 新目录树快照；
4. test split 的 prediction/metrics 覆盖报告；
5. 所有遗留 `pressure_tookit` 命中的解释；
6. 旧树删除候选清单，不执行删除；
7. 未完成项、数据缺口和恢复办法。

## 8. 验收标准

- `Baselines/` 只承担源码职责，不产生新的正式结果。
- pressure_toolkit 的输入和过程输出全部指向 `AnysoleWorkspace/derived/pressure_toolkit/`。
- `results/baselines/pressure_toolkit/` 只包含非空的 `predictions/` 和 `metrics/`。
- 每个正式 baseline 均有稳定的 `predictions/` 和 `metrics/` 消费入口；训练型模型才要求 checkpoint。
- FPP-Net V2T 与 VP-MoCap V2M 的结果目录、注册名称和校验 schema 已分离。
- exporter、validator、registry 和 display 对同一模型使用相同 canonical 路径。
- pressure_toolkit 的公共 PVE/shape 类单元格为 `—`，不存在用 GT beta 或 template 补值的路径。
- test split 的 prediction 数量、帧数、valid mask 和 provenance 与 manifest 一致。
- 新 pipeline 不再生成 `pressure_tookit` 拼写的目录。
- 旧 61 GB 树保持原样，直到用户和主 agent 完成最终查验并另行授权删除。
