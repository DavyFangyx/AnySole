## §3 指标与键名

- **两文件口径**：明细 `<model>/metrics/<split>.json` + 简略 `<model>/metrics/<split>_brief.json`（AnySole 侧落点 `anysole/eval.py:841`（brief）/`:845`（明细），写盘经 `anysole/utils/eval_protocol.py`）。
- 简略文件：组序固定 `("T2M", "V2M", "VT2M", "V2T", …)`。
- **foot sliding 单一公式**：唯一实现 `anysole/utils/metrics.py:364 foot_sliding_joints`。
  - 接触判据 = GT 足速 < 0.3 m/s，**只看 GT**（与模型输出、触觉、模板、shape 无关；`metrics.py:390`）——对所有模型同一规则、无自由度；
  - 指标值 = 接触 (帧,关节) 对上**预测**位移均值（mm）；
  - 主模型与基线 import 同一函数对象（`Baselines/utils/solver.py:32`），消费端一致。
- **两套关节集**（按协议取，`Baselines/utils/protocols.py:77-80 PROTOCOL_FOOT_NAMES`）：
| 协议 | 四关节 | 语义对应 |
| --- | --- | --- |
| `smpl24` | left_ankle / right_ankle / left_foot / right_foot | ankle ↔ Foot、foot ↔ ToeBase（每足 2 点） |
| `bvh23` | LeftFoot / RightFoot / LeftToeBase / RightToeBase | 同上，另一侧 |

- 跨协议**接触帧总体不同**（分母不同：同公式、不同样本总体）——`foot_sliding_mm` 跨协议行**不作排名**（`04_E_评估收尾.md` §5.1）。
- **`pve_mm` 正式启用（U7 拍 A，2026-10-01）**：保留在公共比较表列（"降为明细"备选被否决）；随行项 = 三基线 provenance 元数据统一（E6，`04_E_评估收尾.md` §5.4）。

> **表注**：`pve_mm` 数值含**拟合族**（pressure_toolkit / VP-MoCap）与**预测族**（MotionPRO），**跨族不作排名**。

  1. **能力 ≠ 数组存在**——以"模型真实输出什么"为准，不以文件里恰好存在某数组为准；
  2. **provenance 不参与门控**——`sources`/`approved` 只作审计元数据；任何协议例外必须落成真实生成能力 + 对应预测字段；

- 缺失能力/数据一律标 `—`（`not_applicable` / `invalid`），不写 0、不静默补 GT/模板/启发式。
