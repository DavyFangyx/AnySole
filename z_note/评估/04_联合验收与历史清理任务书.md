# 联合验收与历史清理任务书

> 负责人：主 Agent + 用户  
> 前置条件：任务 01、02、03 均提交完成报告。  
> 本任务是唯一允许实施最终结果删除的阶段；前三个 Agent 只能提交候选清单。

## 1. 目标

联合确认以下内容已经形成闭环：

1. 指标确实来自模型真实输出或批准的确定性派生量。
2. 各模型评测使用正确的原生表示和对应 GT。
3. 过程文件、最终预测和最终指标位于正确根目录。
4. results_display 已完全切换到新协议和新路径。
5. 删除范围精确、可审查，不误删 checkpoint、正式 prediction、native metrics 或探针结果。

## 2. 开始验收前必须收集

- Agent A 的能力矩阵、指标输入要求、单元测试结果。
- Agent B 的迁移 manifest、文件数/字节/hash 核验、canonical path 表。
- Agent C 的 R_Test1/2/3/4 产物和旧派生候选清单。
- 当前 `git status --short`，用于区分本轮改动和用户原有改动。
- 当前磁盘空间，以及旧树和新树各自大小。

任何一项缺失时，不进入删除阶段。

## 3. 模型能力逐项验收

### AnySole motion

- pose、root translation、root rotation 来自模型输出。
- 支持的公共指标有实际数值。
- contact 为 `—`，不能继续把运动学推导结果放入正式表。
- PVE 若保留，必须符合任务 01 对 AnySole 的批准口径。

### MotionPRO

- pose、translation、rotation 的导出与评测一致。
- 原 evaluator 缺少而真实输出足够的指标已经由公共求解器补齐。
- contact 为 `—`。

### pressure_toolkit

- pose、translation、root rotation、joints 可追溯到原生拟合结果。
- `pve_mm`、`shape_vertex_std_mm` 和其他 shape/vertex 公共指标全部为 `—`。
- 模板 vertices 只用于原生结果或可视化，没有通过 GT beta 或模板替换获得公共 PVE。
- 关节、轨迹、orientation、temporal 指标只在真实输出满足条件时计算。

### VP-MoCap / FPP-Net

- V2M 显示名明确为 `VP-MoCap (FPP-Net + PoseTransOpt)`。
- motion 结果确实来自 PoseTransOpt，不归因于 FPP-Net 单模型。
- FPP-Net V2T 与 VP-MoCap V2M 使用不同正式结果根。
- V2T 恰好九项。

### Step2Motion

- 正式主干配置输入维度为 50。
- 数据包含 BVH 派生近似 IMU 通道。
- checkpoint 中存在并实际加载 `model_trans.pth`。
- root/world 轨迹指标来自 translation head，而非 GT fallback。
- MPJAE、PVE、shape、contact 为 `—`。
- no-IMU 仅存在于实验/探针区，不出现在正式 registry 和主排名。

## 4. 协议与数值验收

- SMPL prediction=GT 时，SMPL 原生可用指标为零。
- BVH-23 prediction=GT 时，BVH 原生可用指标为零。
- 两条链路均不经过 common19。
- root orientation：相同旋转为零；固定 yaw 偏置不影响 drift；线性漂移符合预期；跨 `±180°` 不跳变。
- 缺少必要字段时，求解器返回明确的不适用或失败原因，不静默补 GT。
- R_Test2 和 R_Test4 对同一 V2T archive 的九项数值一致。
- session 集来自同一 canonical split；valid frame 数和聚合权重可追溯。

## 5. 目录验收

正式结果根应为：

```text
results/baselines/MotionPRO/
results/baselines/Step2Motion/
results/baselines/pressure_toolkit/
results/baselines/FPP-Net/
results/baselines/VP-MoCap/
```

要求：

- 每个正式 baseline 有 `predictions/` 和 `metrics/`。
- 学习模型可有 `checkpoints/`；优化方法不创建空 checkpoint。
- `results/baselines/pressure_toolkit/` 顶层不含日期、subject、session、gt depth、OBJ、YAML 或 temp。
- pressure_toolkit 的 fitting 原生产物完整位于 `AnysoleWorkspace/derived/pressure_toolkit/`。
- 生产端 dry-run 不再把过程文件指回 results。
- exporter、validator、registry、display 使用相同 canonical 路径。

## 6. 删除候选

### 展示端旧派生结果

新结果通过验收后，候选删除并重建：

```text
results_display/ResultTest/R1Test_visualize/compare/
results_display/ResultTest/R2Test_compare/
results_display/ResultTest/R3Test_traj/compare/
results_display/ResultTest/R4Test_v2t/
```

以及各模型目录中满足以下条件的文件：

- schema v1 的 comparison 文件；
- 元数据含 `joint_set=common19` 的 comparison 文件。

禁止使用宽泛通配符删除整个 `results_display/ResultTest/`。

### pressure_toolkit 旧树

只有 Agent B 的迁移 manifest 全部匹配后，才把以下项目列入实际删除命令：

- 已迁移的旧 `gt_depths/`、`meshes/`、`results/`、`yamls/`、`temp/`、`logs/`；
- 已迁移的顶层 `Sxxxx/` CLIFF 初始化副本；
- 拼错的 `results/baselines/pressure_tookit/`；
- 错误的 `results/VP-MoCap/`；
- 经核验没有独有结果的 `results/offline/pressure_toolkit/`。

约 61 GB pressure_toolkit 旧树必须按 date/subject/session 分批核对。不得仅凭总大小相同删除。

## 7. 永久保留

- 正式 checkpoint。
- canonical predictions。
- native metrics 和新公共 metrics。
- Step2Motion no-IMU 探针的数据、checkpoint、预测和报告。
- 尚需追溯的 `results/backup/` 历史实验。
- 用户原有、与本任务无关的工作区修改。

此前误删且无法从 Git 恢复的以下目录只保留清理记录，不伪造恢复：

```text
results/baselines/MotionPRO/checkpoints_smoke/
results/baselines/pressure_toolkit_ab_s1/
results/baselines/pressure_toolkit_ab_s2/
```

## 8. 删除执行规则

1. 先输出将删除的逐项绝对路径、文件数和大小。
2. 主 Agent 与用户共同确认清单。
3. 优先移动到同文件系统隔离区；空间不允许时才执行直接删除。
4. 每批完成后重新运行 validator 和 results_display 消费检查。
5. 记录删除时间、范围、可恢复性和释放空间。
6. 任一 canonical prediction/metric 缺失时立即停止后续批次。
