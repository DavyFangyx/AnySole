设计原则：

1. **配置跟着模型走**：`configs/v1.yaml` 是 anysole 私有，进 `anysole/configs/`。
2. **数据构建代码随数据走**：所有"生产/准备中间数据"的代码（workspace 管理、
   PressureWasher、接触 npz、manifest 生成、数据质检、HRNet 缓存）统一放
   `AnysoleWorkspace/tool/`，与它生产的数据属同一组件；仓库根不设 `tools/`。
3. **实验脚本与实验产物分离**：代码进 git 的 `experiments/`，产物留在 gitignored 的
   `display/`。现在的 `results_display/script/` 是唯一被 gitignore 豁免的产物目录，
   等于让"代码"寄生在"产物"目录里活命 —— 这是 F 组件最大的结构问题。
4. **笔记目录不放代码**：z_note 只留 md。
5. **单一事实来源**：路径常量只认 `anysole/types.py`（或让它读 workspace.yaml，见 §P2-12），
   消灭 types.py / train.py DEFAULT_PATHS / configs/v1.yaml / pwlib/paths.py 四重硬编码。
