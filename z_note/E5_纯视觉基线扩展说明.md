## 2 实现设计（P0：WHAM）

### 2.0 共同骨架：管线不变，只在中间加料

`AnysoleWorkspace/tool/adapters/visual_baselines/generate.py` 的 `generate_wham`
已经是一条完整管线：

```
recording_frames(row, cam)      # row["video_path"]/3/*.jpg
  -> unit_frame_paths(...)      # 按墙钟把 unit 帧映射到录像帧
  -> build_sequence_video(...)  # frames.txt + ffmpeg concat -> sequence.mp4
  -> bbox_sidecar(...)          # 干净前端 bbox.npz -> target_bboxes.json
  -> demo.py --video --target_bboxes --save_pkl --estimate_local_only
  -> compact_wham(...)          # wham_output.pkl -> result.pkl 契约
```

**加料点只有两处，且都不碰 bbox 与 ffmpeg 命令：**

1. `build_sequence_video` 收到的 `frame_paths` —— 把干净 JPEG 换成退化后的图像文件；
2. `frames.txt` 的**路径序列** —— 断流轴把某帧的路径替换为最近活帧的路径。

第 2 处不落任何图像，断流轴因此是纯文本改写（与 `make_gap_cache.py` 的锚点律完全
同源：同一 `session_phase` / `gap_length`，**直接 import 复用，不许另写一份**）。

退化函数同样复用 `anysole/data/extract_hrnet.py` 的 `apply_exposure_gain` 与
`occlude_lower_strip`，**不许复制实现**——两条路径（模型缓存 / 基线图像）的退化必须
逐位同源，否则对照表里 Δ 的差包含了「两套退化写得不一样」。

> 现成缺口：`generate_wham` 里没有这两个钩子。新增参数
> `--degrade {none,occ:E,exp:G,gap:R}`，在 `generate_wham` 内解析后传给新增的
> `stage_frames(...)`；默认 `none` 时行为与今天逐位一致（这是 G1 门）。

### 2.1 图像暂存：不污染、不重复编码

每档每会话建一次性暂存目录，**写 PNG 不写 JPEG**（避免二次有损）：

```
work/visual_baselines_degraded/<cond>/<date>/<subject>/<session>_c3/frames/
```

流程：读干净 JPEG → 解码 → 施加退化 → 写 PNG → `frames.txt` 指向 PNG →
`build_sequence_video` 跑**与今天逐字节相同**的 ffmpeg 命令（`-r 30 -c:v libx264
-pix_fmt yuv420p`，`generate.py:163`）。

- **空间轴**：`occlude_lower_strip(rgb, box, frac, fill)`，`box` 用该帧的干净前端
  bbox（与模型缓存同一框）。`fill` 取主实验用的那一档（默认 `black`，与 occ 缓存
  一致；若主实验用了 blur，两处必须同档）。
- **光度轴**：`apply_exposure_gain(rgb, G)`，整帧 `clip(rgb*G,0,255)`。
- **时间轴**：**不落图**。`frames.txt` 里把冻结帧的路径写成锚点帧的路径，ffmpeg
  照常编码。`session_phase` / `gap_length` 直接 import；`cycle=100, seed=0` 与
  `make_gap_cache.py` 完全一致。第 0 帧强制活。

暂存目录跑完即删（每档峰值 ≈ 12915 张 PNG，按 1240×1624 约几十 GB，必须逐会话
生成—编码—删除，不能一次性铺满全档）。

### 2.2 bbox 与检测的不对称是**故意的**，且已成立

三条外部基线（WHAM / SAM3DB / GVHMR）在当前管线里全部**吃外部注入的 bbox**
（`bbox_sidecar` ← 干净前端 `bbox.npz`），不跑自己的检测器。所以退化图像不会让
检测崩掉，与 V7_Cv5 的「bbox 保持干净」完全平行。**这一点不需要改动，是现状。**

### 2.3 断流轴的模型差异

- **WHAM（流式）**：有跨帧状态，断流 5 档必须按 2.1 的帧路径改写 + 重跑。
- **SAM3DB（逐帧，P1）**：冻结输入 ⟺ 冻结输出，干净跑一次后按锚点索引重排即得
  五档断流结果，零推理成本。
- **GVHMR（流式，P2）**：与 WHAM 同理，需重跑。

### 2.4 三轴落地（WHAM）

| 轴 | WHAM 做法 |
|---|---|
| 干净 | 复用现有预测，不重跑 |
| 空间 occ 5 档 | 图像加料（bbox 底部涂黑）+ 重编码 + 重跑 |
| 光度 exp 6 档 | 图像加料（整帧增益）+ 重编码 + 重跑 |
| 时间 gap 5 档 | 仅改 `frames.txt` 的帧路径 + 重跑 |

**WHAM 依赖的图像/退化缓存与 V7_Cv5 主实验同源**：曝光/断流/遮挡的退化函数与
锚点律必须逐位一致（G2/G3）。当前农场（11-04）：三轴 16 档缓存已全量齐
（test 36 + val 12），P0 可直接开跑。

## 5 验收门（WHAM）

| 门 | 判据 | 不过怎么办 |
|---|---|---|
| **G1 零回归** | `--degrade none` 时 `frames.txt` 与 ffmpeg 命令与今天逐字节相同；1 会话 `sequence.mp4` 的 sha256 与现有干净产物一致 | 说明钩子改变了默认路径，回滚钩子 |
| **G2 退化同源** | 对某会话，`stage_frames` 产出的 PNG 与 `extract_hrnet` 内部施加退化后的数组逐位相同（max abs = 0） | 说明两处退化不同源，必须复用函数而不是重写 |

G2 是这一批里最关键的门：它保证「模型看到的退化」与「基线看到的退化」是同一个

## 6 论文口径与已知边界

1. **最终口径是三个外部纯视觉基线（GVHMR / SAM3DB / WHAM）**；当前阶段只交付
   WHAM，正文/表格中如实标注「WHAM first, other baselines pending」。
2. **五主指标全为关节口径**（`metrics.py`：`foot_sliding_joints`、
   `ground_penetration` 吃 `(T,J,3)` 关节），所以不需要存 6890 顶点；顶点只用于
   PVE，而 PVE 跨族不排名（U7）。
3. **H.264 交互**：退化图像要经一次 `libx264` 有损编码，在 G=0.05 这种近全黑档，
   编码器噪声相对信号占比最高，可能与干净档不等价。缓解：暂存用 PNG、ffmpeg
   参数与干净档逐字节相同，让它成为装置的常数而不是变量；论文里不宣称光度轴的
   细粒度单调性。
4. **b 常数沿用**：退化档沿用干净档拟合的世界平移。若某档 b 漂移显著，说明该档的
   退化改变了基线的根位置估计——这是**结果**不是 bug，如实呈现。
5. **val 不跑**：WHAM 只跑 test 36 会话。val 需另建时按同脚本逐日期重拟合 b。
6. **bbox 不对称**：三条基线全部吃干净前端 bbox（现状），与 V7_Cv5 一致；这是故意
   的，论文里声明一句即可。

## 附录 A：CLIFF 解码级对照（口径外，暂不做，技术留档）

原稿曾把 CLIFF 头解码列为「层 1」，理由是缓存每行 2051 维 = HRNet 2048 +
