## 5. 单个环境无法使用，原项目中的 Baselines/MotionPRO/requirements.txt 失效

使用原环境安装会卡在 mmcv 的 wheel 上

  失败点有两层，叠在一起。

  第一层：版本墙。
  Baselines/MotionPRO/requirements.txt 钉死了
  torch==2.4.0 和 mmdet==3.3.0。mmdet 3.3.0 自
  己又钉死了：

  mmcv >= 2.0.0rc4  且  mmcv < 2.2.0

  OpenMMLab 给 cu121 + torch2.4 + cp38 只提供了
  mmcv-2.2.0。这个包一装，import mmdet 会直接
  assert 失败。给 torch 2.4 用的、且满足 <2.2.0
  的预编译包，没有。所以不是“再试一次 mim”，是
  官方依赖组合本身对不上。

  第二层：源码编译也编不了。
  没有对应 wheel 时，pip/mim 会去编 mmcv。你这
  台机器上：

  - CUDA_HOME=/usr/local/cuda-12.2
  - 这个目录已经不存在
  - 系统里实际是 /usr/local/cuda-13.3
  - 所以去找 /usr/local/cuda-12.2/bin/nvcc，报
    No such file or directory

  就算把 CUDA_HOME 改成 13.3，也不该拿 CUDA
  13.3 的 nvcc 去给 torch 2.4+cu121 编 mmcv。
  PyTorch 自带的是 CUDA 12.1 运行时，toolkit 对
  不上，编出来也很容易废。

  所以你的判断是对的：touch_gait 这个 torch 2.4
  + cu121 底座，配不上 mmdet 3.3.0 要的那版
  mmcv。原 README 漏写了 mmcv/mmengine；本地清
  单又要求“不要额外装 mmcv”。按那套走，gen_bbox
  过不去。

  能走通的是拆环境，而且 bbox_scan 的 torch 选
  对了。torch 2.1.2+cu121 有现成的 mmcv-2.1.0
  wheel，正好落在 mmdet 3.3.0 的窗口里。现在这
  个环境只是没装完：有 torch，没有 opencv、
  mmdet、mmcv。

  在 bbox_scan 里装预编译包，不要再源码编译：

  conda activate bbox_scan
  python -m pip install opencv-
  python==4.10.0.84 numpy==1.23.0
  mmengine==0.10.7 mmdet==3.3.0
  python -m pip install mmcv==2.1.0 -f
  https://download.openmmlab.com/mmcv/dist/cu121/torch2.1/index.html
  python -c "import cv2, mmcv, mmengine, mmdet;
  from mmdet.apis import init_detector;
  print(mmcv.__version__, mmdet.__version__)"
  cd /data/fangyuxuan/projects/gait/Baselines/
  MotionPRO
  python -m lib.util.gen_bbox
